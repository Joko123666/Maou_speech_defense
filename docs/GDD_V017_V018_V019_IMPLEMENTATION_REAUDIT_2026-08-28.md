# GDD v0.17 → v0.18 → v0.19 구현 재점검

- 점검일: 2026-08-28 (Asia/Seoul)
- 대상 문서: `godot_formation_defense_gdd_v0_17.md`, `godot_formation_defense_gdd_v0_18.md`, `godot_formation_defense_gdd_v0_19.md`
- 대상 구현: 현재 프로젝트의 코드, 씬, `.tres` 데이터, 저장·UI·계약 테스트, 최근 런타임·밸런스 감사 결과
- 결론: **보완 완료. 최초 재점검에서 확인한 기능 차이 1건, 온보딩/정보 표시 누락 2건, 관측성 누락 1건을 모두 구현하고 회귀·런타임·모바일 UI·배속 등가성 검증을 통과했다.**

## 1. 판정 원칙

세 GDD는 각각 독립 제품 사양이 아니라 누적 문서다. 따라서 다음 순서로 판정했다.

1. v0.17의 온보딩·메타 해금·상점·도감·Challenge 증분을 먼저 확인한다.
2. v0.18의 POWER/SPEED/RANGE 공통 언어와 후보·심복 초과성장을 추가 확인한다.
3. v0.19에서 v0.18을 대체한 결정을 마지막으로 적용한다. 특히 일반 POWER/SPEED/RANGE 전역 카드는 v0.19에서 제거 대상이므로 현재 부재가 정상이다.
4. `[확정]`, `[확정 구조]`, `[확정 방향]`과 통합 완료 기준은 구현 계약으로 본다. `[제안]`, `[검증]`, `[현재 보류]`, `[미구현]`은 채택되지 않았다는 이유만으로 결함 처리하지 않는다.
5. 문서보다 실행 코드와 테스트가 우선이지만, 테스트가 GDD 의미를 충분히 검사하지 않는 경우에는 통과 결과와 별개로 사양 차이를 기록한다.

문서 규모는 v0.17 5,879행, v0.18 6,318행, v0.19 6,335행이다. v0.17→v0.18은 주로 공통 3축·초과성장 증분이고, v0.18→v0.19는 일반 전역 카드 제거와 아티팩트 시스템 추가·정리다.

## 3. 발견 사항

아래 설명은 최초 재점검 당시의 원인 기록이며, 각 항목의 완료 기준과 현재 해결 상태를 함께 보존한다.

### F-01 · 해결됨 · 마력 전도탑 RANGE/연결 거리 분리

GDD v0.18은 범위를 핵심 공간 영향력으로 정의하고 마력 전도탑을 `전도 연결 거리`에 매핑한다(`godot_formation_defense_gdd_v0_18.md:3571`, `:3582`, `:3603`, `:3767`). v0.19도 같은 `link_range` 언어를 유지한다(`godot_formation_defense_gdd_v0_19.md:3623`). 실제 데이터도 `data/meta/defense_stat_catalog_v0_19.tres:194`에서 표시명을 `마력 연결 거리`, modifier 키를 `link_range`로 선언한다.

그러나 런타임은 다음과 다르다.

- `scripts/battlefield/tower_column.gd:338`의 `get_attack_range()`가 모든 병종의 RANGE 기본값을 일반 공격 사거리에 적용한다.
- `scripts/game/game_controller.gd:3919`의 네트워크 경로는 모든 마력 전도탑을 최근접 순서로 연결한다.
- `scripts/game/game_controller.gd:3928`의 수집 함수에는 거리 판정이 없다.
- 그 결과 멀리 떨어진 전도탑도 네트워크 릴레이 수·피해 배율·왕복 전도 경로에 포함되며, RANGE 증가는 실제 `link_range` 대신 첫 표적 공격 사거리를 늘린다.
- `tests/contracts/v019_m4_defense_stat_contract_test.gd`는 27개 데이터와 고블린 창병의 일반 공격 사거리만 실행 검증하므로 이 차이를 발견하지 못한다.

권장 완료 기준:

- 현재 연결점에서 `link_range` 이내인 전도탑만 결정적으로 다음 릴레이 후보가 된다.
- 연결 가능한 노드가 없으면 경로 생성을 중단한다.
- RANGE 0/증가 전후에 경계 안·밖 노드가 실제 네트워크 수와 피해 경로를 바꾸는 계약 테스트를 추가한다.
- 전도탑의 첫 표적 사거리를 함께 늘릴지 여부를 명시하고, 문서대로라면 `link_range`와 분리한다.

해결: `TowerData.link_range_cells`를 기본 1.5칸으로 정의하고 `TowerColumn.get_chain_link_range()`가 실제 열·행 간격과 `link_range` RANGE 보정을 계산한다. 릴레이 경로는 현재 연결점에서 닿는 가장 가까운 전도탑만 추가하고 더 이상 닿지 않으면 중단한다. RANGE 증가 전후로 먼 중계기 포함 여부가 바뀌되 첫 표적 공격 사거리는 변하지 않는 계약·게임플레이 테스트를 추가했다.

### F-02 · 해결됨 · 60초 튜토리얼 후보 목표·심복 역할 안내

v0.17 확정 방향의 정확한 여섯 학습 항목은 `후보의 역할 → 심복의 역할/이동 → 고블린 배치 → 고정 성장 → 보스 → 후보 스킬`이다(`godot_formation_defense_gdd_v0_17.md:306-330`). 첫 항목은 후보가 연설을 끝낼 때까지 지킨다는 목표 소개다.

현재 `scripts/tutorial/tutorial_director.gd:7`의 여섯 단계는 `심복 이동 → 고블린 배치 → 자동 방어 관찰 → 고정 성장 → 보스 → 후보 스킬`이다. `observe_defense`가 들어오면서 후보 보호 목표가 독립 학습 항목에서 빠졌고, 첫 안내 문구도 바로 칸다 이동을 지시한다. `scripts/game/game_controller.gd:332` 역시 전달받은 일반 안내를 표시할 뿐 후보 목표를 별도로 제시하지 않는다.

튜토리얼 시간, 고정 후보/심복/병력, 지정 배치, 고정 성장, 55초 보스, 후보 스킬, 배속·리롤·Challenge 격리와 정산 격리는 정상이다. 따라서 튜토리얼 전체 미구현이 아니라 **학습 내용 한 항목의 대체**다. `V019M2TutorialContractTest`는 정확히 6단계와 상태 전이만 검사해 문구 의미를 검증하지 않는다.

권장 완료 기준:

- 시작 오버레이 또는 첫 단계 안에 `파르태손의 연설 종료까지 보호` 목표를 명시한다.
- 여섯 단계 구조를 유지하려면 후보 목표 소개를 첫 단계의 사전 안내로 넣고, 칸다의 직접 조작·회수 역할도 같은 단계에서 유지할 수 있다.
- 계약 테스트에 후보 보호 목표와 심복 직접 조작 의미의 필수 문구 또는 안정 ID를 추가한다.

해결: 정확히 6단계인 기존 흐름은 유지하면서 첫 단계에 `파르태손의 연설 종료까지 보호` 목표와 칸다의 직접 전투·유세 열기 회수·클릭/드래그 이동을 함께 표시한다. 전용 계약은 세 의미가 모두 존재하는지 검사하며 실제 튜토리얼 씬과 Forward Mobile 스냅샷을 재검증했다.

### F-03 · 해결됨 · 도감 인물·병력 상세 필드

v0.17 도감의 확정 방향은 후보의 팩션·현재 지지도·승격 상태·프로필/대사, 심복의 선호 후보, 수비병력의 출신 팩션/기술 등을 포함한다(`godot_formation_defense_gdd_v0_17.md:617-641`).

현재 `scripts/meta/codex_service.gd`의 상태는 다음과 같다.

- 후보 항목(`:33`)은 이름·칭호·설명·전투 수치·성장·전용 병력/편대를 표시하지만 현재 지지도, 승격 상태, 명시적 팩션과 대사는 표시하지 않는다.
- 심복 항목(`:65`)은 전투·이동·회수 수치와 특화를 표시하지만 선호 후보를 표시하지 않는다.
- 수비병력 항목(`:91`)은 역할·기초 수치·관련 편대·특화와 3축 정보를 표시하지만 출신 팩션/기술을 표시하지 않는다.
- 후보/심복/병력/편대/적/용어 6개 분류, 10개 용어·규칙, 실제 적 조우 원장과 미발견 적 잠금은 정상이다.

`V019M3HubCodexContractTest`는 분류 수, 용어 10종과 실제 적 조우 발견을 검사하지만 위 상세 필드는 검사하지 않는다.

권장 완료 기준:

- 기존 캠페인·세이브 데이터에서 후보 팩션, 현재 지지도, 승격 여부를 읽어 후보 상세에 표시한다.
- 심복 데이터의 선호 후보를 세계관 정보로 표시하되 보너스로 오해되지 않게 설명한다.
- 병력 데이터에 출신 팩션/기술의 권위 필드가 없다면 먼저 데이터 소유권을 정하고 도감은 그 값을 소비한다.
- 대표 후보·심복·병력 각각 하나에 대한 상세 필드 계약과 UI 스냅샷을 추가한다.

해결: 후보는 팩션·현재/필요 지지도·당선 상태·통치 지지율/반응과 유세 구호를, 심복은 선호 후보와 별도 조합 보너스가 없음을 표시한다. 일반 병력은 `TowerData`의 출신 팩션·기술 권위 필드를 소비하며, 고유 친위대와 대체 프로필은 안전한 폴백을 사용한다. 대표 후보·심복·병력과 일반 9병종 기술 필드를 계약으로 고정하고 후보/병력 도감 스냅샷을 확인했다.

### F-04 · 해결됨 · 초과성장 최초 제안 시각 감사

v0.18 핵심 관측 지표에는 후보/심복 초과성장 최초 등장 시점과 평균 선택 횟수가 포함된다(`godot_formation_defense_gdd_v0_18.md:5879-5880`).

현재 `scripts/game/run_metrics.gd:543`의 `record_choices()`는 안정 ID별 제안 횟수를 집계하고, `:554`의 선택 이벤트는 경과 시각과 성장 트랙을 저장한다. 따라서 초과성장 평균 선택 수와 첫 **선택** 시점은 구할 수 있지만 첫 **제안** 시각은 집계 데이터만으로 복원할 수 없다. 아티팩트에는 별도 시간 이벤트 원장이 있으나 초과성장에는 없다.

권장 완료 기준:

- 제안 이벤트에 `elapsed`, `category`, `data_id`, `track`을 저장하거나 `first_offer_by_track`을 추가한다.
- 후보·심복 초과성장 최초 제안 시각과 완주당 평균 제안/선택 수를 감사 요약에 포함한다.
- 선택하지 않은 첫 제안도 보존되는 계약 테스트를 추가한다.

해결: `RunMetrics`가 후보/심복 초과성장 제안마다 `elapsed/category/data_id/track`을 저장하고 성장 타임라인에 전체 제안 및 계열별 최초 제안을 반환한다. `BalanceAuditSummary`는 계열별 제안·선택·제안 런 수·완주당 평균·평균 최초 제안 시각을 집계한다. 선택하지 않은 후보 제안도 보존되는 계약과 schema v19 매트릭스 결과를 확인했다.

## 4. 버전별 세부 확인

### v0.17

정상 확인:

- 신규 계정은 파르태손/칸다와 초기 4병종만 시작하며 Challenge 0이 고정되고 첫 승리 전 Challenge UI가 숨겨진다.
- 후보와 심복의 최초 클리어 원장은 독립적이며 같은 첫 승리에서 각각 다음 1명과 Challenge 다음 1단계만 열린다. 재클리어·건너뛰기는 차단된다.
- 후속 5병종은 220/260/320/340/380 자금으로 업적 발견과 무관하게 자유 구매되고, 구매 직후 구성 병력 기반 관련 편대가 자동 적격화된다.
- 유세 자금, 후보 지지도 계산, 승격, 통치 지지율/칙령 상태가 저장·정산·허브 UI에 연결된다.
- Challenge는 0→10 순차 진행이고 패배는 진행도를 올리지 않는다.
- 도감은 6개 분류와 실제 조우 기반 적 발견을 제공한다.

보완 완료:

- F-02의 후보 보호 목표와 심복 직접 조작·회수 역할을 첫 단계에 복원했다.
- F-03의 후보·심복·병력 상세 필드를 실제 캠페인·세이브·병력 데이터에서 표시한다.

결함으로 보지 않은 항목:

- 후보별 승격 후 특수능력은 v0.17 자체가 `[특수능력 미구현]` 및 미확정 항목으로 둔 부분이다. 현재 프로젝트의 칙령·통치 기능이 존재하지만, 미정인 별도 특수능력을 구현하지 않았다는 이유로 실패 처리하지 않았다.
- 상태이상 최초 사용/피격 기반 발견 범위는 `[제안]`이므로 현재 용어 항목 상시 공개를 결함 처리하지 않았다.

### v0.18

정상 확인:

- 데이터 카탈로그는 POWER/SPEED/RANGE 3축과 일반 9병종×3축 27개 매핑을 갖는다.
- 친위대에 사용된 같은 일반 병종은 축을 공유하고 후보·심복·소환물은 제외된다.
- POWER는 직접 피해·둔화·취약·넉백의 선언된 값에 연결되고 독/출혈/감전/화상 자체 피해를 중복 증폭하지 않는다.
- SPEED는 행동 주기를 단축하지만 이동속도를 바꾸지 않는다.
- RANGE는 고정값과 병종별 상한을 사용한다.
- 카드·도감은 색만이 아니라 아이콘·축 이름·병종별 의미를 함께 표시한다.
- 후보 2종, 심복 4종의 초과성장 카탈로그와 완료 조건, 18% 성장 슬롯 경쟁, 화면당 최대 1장, 반복 적용, 전투 배율·결과 스냅샷이 연결된다.

보완 완료:

- F-01의 전도 연결 거리와 첫 표적 사거리를 분리하고 거리 경계 테스트를 추가했다.
- F-04의 선택 전 제안 이벤트·최초 제안 시각·계열별 평균을 schema v19에 추가했다.

v0.19에 의해 정상 대체된 항목:

- v0.18은 POWER/SPEED/RANGE 전역 카드를 요구했지만 v0.19는 공통 언어·병종별 매핑만 유지하고 일반 전역 카드를 제거한다. 현재 제안·적용 경로가 `global_upgrade`를 거부하고 레거시 결과 읽기만 유지하는 것은 최종 GDD에 맞다.

### v0.19

정상 확인:

- 첫 레벨업은 일반 편대가 0개인 동안 병력 세트 1장을 보호한다. 후보/심복/친위대/아티팩트 주입도 이 필수 슬롯을 침범하지 않는다.
- 일반 POWER/SPEED/RANGE 전역 카드는 활성 제안·적용·전투 효과에서 제거됐고 위조 선택도 거부된다.
- 초기 아티팩트 카탈로그는 안정 ID 18종이며 일반 수비병력, 후보, 심복, 친위대와 독/출혈/감전/화상을 포괄하고 단순 강화와 trade-off 효과를 함께 가진다.
- 출현 계열 확률은 5.5%, 일반 3택 한 화면 최대 1장이고 실제 적격한 아티팩트만 확정 카드로 제시한다.
- 인벤토리는 런 한정 고정 6칸, 중복 불가, 창고 없음이며 빈 슬롯 장착과 가득 찬 상태의 교체/포기가 원자적으로 처리된다.
- 교체 UI는 신규 효과와 기존 6칸을 함께 표시하며 결정을 끝낼 때까지 보상 큐를 정지한다. HUD는 6칸 요약과 상세를 제공하고 모바일 터치 대상은 48px다.
- 아티팩트 효과는 일반 3축, 후보, 심복, 친위대, 상태에 실제 연결되고 일반 POWER가 공통 상태 피해를 우회 증폭하지 않는다.
- 보스 처치, 특수적, 맵 드롭, 상점 등 보류된 별도 획득 경로는 연결되지 않았다.
- 결과·체크포인트·감사에는 제안, 획득, 포기, 교체, 첫 6칸 완성 시각, 최종 인벤토리, 대상군, 안정 ID별 비율과 관측 출력 기여 추정이 보존된다.

남은 검증 한계:

- 최근 동일 3시드 600초 감사에서 disabled와 normal 모두 최종 보스 도전 3/3으로 기술·밸런스 게이트를 통과했다. normal은 완주당 평균 제안·획득 1.33회였으나 자연 표본은 제안 4건, 선택 4건, 포기·교체 0건이다.
- 강제 계약 테스트가 6칸 포화·포기·교체 기능을 검증하므로 기능 결함은 아니지만, 자연 플레이에서의 선택률·포기율·교체율과 후보/빌드별 고점 효과를 일반화하기에는 표본이 부족하다.
