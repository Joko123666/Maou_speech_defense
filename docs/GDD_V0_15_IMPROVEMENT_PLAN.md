# Formation Defense GDD v0.15 개선 계획

- 기준일: 2026-08-25
- 기획 기준: `godot_formation_defense_gdd_v0_15.md`
- 구현 기준선: GDD v0.14 M0~M4 완료본
- 문서 성격: v0.15 적 카탈로그·Faction Prelude 증분의 구현 순서, 데이터 경계, 완료 조건
- 모바일 실기 검증: 사용자 재개 지시 전까지 보류

## 1. 결론

v0.15의 최우선 작업은 기존 18개 행동 템플릿을 수치만 바꾸는 일이 아니다. 활성 적 콘텐츠를 **공용 적 7종 + 팩션 적 5종**으로 교체하고, 다음 공식 난입의 진영을 미리 보여주는 **Faction Prelude**를 현재 Base/Bonus Spawn Budget 안에서 구성하는 작업이다.

실행 순서는 다음과 같다.

```text
M0 계약·이관 경계 동결
→ M1 적/스폰 데이터 모델 분리
→ M2 공용 적 7종
→ M3 팩션 적 5종
→ M4 Faction Prelude·패킷 조합
→ M5 자산·HUD·도감·메트릭
→ M6 장기 밸런스·1×/2×/3× 감사
→ M7 표현·모바일·배포 승인
```

v0.14 M5에서 예정했던 상태·친위대 성장과 Bonus Spawn XP 4.51% 조정은 M6로 이관한다. 적 수, 비용, 사망 보상, 패킷 구성이 전부 바뀌기 전에 XP 공급률을 먼저 조정하면 곧바로 재튜닝해야 하기 때문이다.

## 2. 유지할 기준선과 교체할 영역

### 유지

- Godot 4.7 Mobile 렌더러, 1280×720 가로 화면
- 4×6 블록 보드와 일반 편대 49종의 v0.14 분포
- 후보·심복·친위대 성장과 4회의 공식 난입
- `standard_20m`, `StageData.final_boss_id`, 보스·후보·세이브·상점·업적 안정 ID
- `StageRuntimeBossPlan`의 보스 순서·시간·`faction_id`
- Base Budget, Bonus Budget, Alive Pressure, 보스 비예산 처리
- 보스 활성 중 Base 유지와 Bonus ×0.3 초기안
- 게임 시간 1/60초 고정 틱 및 1×/2×/3× 논리 등가성
- 외부 콘텐츠 팩의 안정 `StringName` 참조 철학

### M0 진단 당시 교체 대상

- 활성 일반 적 18종과 `normal/fast/swarm/.../zigzag/taunter` 가중치 테이블
- 분열·지원·정화·위상이동·랜덤 지그재그 등 구형 적 행동을 목표 적 풀에서 사용하던 구조
- 돌파대·호위대·공성대 3종만으로 구성된 현재 패킷 카탈로그
- 모든 일반 적을 다섯 진영의 `supporter_enemy_ids`에 나눠 표시하던 방식
- 적 인스턴스에 진영·그룹·대열·희귀 쿨다운 문맥을 전달하지 않는 현재 스폰 신호
- `source_type` 문자열만 남겨 실제 처치 수비병력을 알 수 없는 피해 귀속

### 재사용할 가장 중요한 연결점

`CampaignStageResolver`는 이미 각 보스 슬롯에 `faction_id`를 기록한다. Faction Prelude는 새 라이벌 추첨기를 만들지 않고 `StageRuntimeBossPlan.faction_id_at(next_boss_index)`를 단일 권위로 사용한다. 활성 선거 캠페인이 없는 고정 스테이지는 명시적 진영 매핑이 있을 때만 Prelude를 켜고, 그렇지 않으면 공용 적만 사용한다.

### Phase 결정

현재의 6개 `SpawnPhaseData`는 예산률·Alive Pressure·패킷 상한을 안정적으로 제공한다. v0.15의 0:00/1:15/2:30/4:00/5:00/6:15/7:30/8:30/10:00 경계는 **적격 시간표와 Prelude 시간표**로 분리한다. M0~M5에서는 6개 예산 Phase를 유지하고, GDD §31의 “4국면 vs 6구간”은 M6 측정 결과가 필요할 때만 A/B한다.

## 5. 데이터·런타임 설계

### 5.1 `EnemyData`와 스폰 프로필 분리

현재 `EnemyData`에 HP·속도·XP와 `spawn_cost`·역할·해금 시각이 함께 있다. v0.15에서는 다음 책임으로 나눈다.

- `EnemyData`: 전투 스탯, 외형, 저항, 선택적 행동 프로필
- `EnemySpawnProfileData`: `enemy_id`, 비용, 역할, 해금, 팩션, 그룹 범위, 희귀 쿨다운
- `FactionPreludeData`: 보스 인덱스, 지속시간, Tier, 팩션 비용 비율 범위
- 선택적 소형 행동 리소스: 이동 경로, 속도 스택, 자가 감소, 사망 비활성화

내장 콘텐츠는 새 프로필을 단일 권위로 사용한다. 외부 콘텐츠 팩에 새 프로필이 없으면 기존 `EnemyData.spawn_cost/role_tags/available_from_seconds`에서 공용 적 호환 프로필을 생성하되, 명시적 팩션 프로필 없이는 Prelude에 참여시키지 않는다.

### 5.2 Spawn Context

현재 `spawn_requested`에 Y·적 데이터·배율만 전달한다. 이를 다음 정보를 보존하는 타입 또는 검증된 구조로 확장한다.

- `packet_id`, `channel`, `spawn_time`
- `faction_id`, `prelude_tier`
- `group_id`, `cohort_id`, `wave_index`
- 고정 사선용 `destination_y`

`group_id`와 대열 축은 적이 생성된 뒤 추정하지 않고 패킷 구성 시 한 번 정한다. 같은 주다긴다 패킷의 두 번째 무리는 반드시 다른 `group_id`를 사용한다.

### 5.3 처치자 귀속

서큐버스 계약을 위해 문자열 `source_type`만으로는 부족하다. 모든 기존 피해 호출을 한 번에 교체하지 않고 선택적 `DamageSourceContext`를 추가한다.

- 소스 종류: 후보, 심복, 일반 수비병력, 친위대, 상태, 소환, 환경
- 일반 수비병력 위치: `placement_id`, 열, 행, `tower_id`
- 마지막 유효 피해 소스와 결정타 소스 분리
- 해제된 Node를 직접 장기 보관하지 않고 안정 위치 참조를 런타임에 재해석

망령은 이 문맥을 사용하지 않고 사망 위치와 보드 셀의 실제 월드 거리를 사용한다. 서큐버스는 결정타가 일반 수비병력일 때만 정확한 행을 비활성화한다.

### 5.4 사망 원인

적 종료 원인을 최소한 `DIRECT_KILL`, `DAMAGE_OVER_TIME`, `SELF_DECAY`, `BREACH`, `DESPAWN`으로 구분한다.

- 심연 피조물의 `DIRECT_KILL`, `DAMAGE_OVER_TIME`, `SELF_DECAY`는 XP 100%
- CC는 사망 원인이 아니라 지연 요소이므로 이후 `SELF_DECAY`도 XP 100%
- `BREACH`는 처치·킬·XP·동료 사망 버프로 기록하지 않음
- 기존 일반 적의 코어 도달 경로가 `died`를 내보내지 않는 계약을 유지

### 5.5 예산 대체형 Prelude

Prelude는 세 번째 예산 채널을 만들지 않는다. Base/Bonus에서 한 패킷이 지출할 총비용을 먼저 정하고, `FactionBudgetLedger`가 해당 비용 중 목표 비율만 팩션 슬롯에 배정한다.

- Tier 1: 15~25%
- Tier 2: 25~35%
- Tier 3: 35~45%
- 이산 비용 때문에 한 패킷에서 정확히 맞지 않으면 다음 패킷에 오차를 이월
- Prelude 전체 누적 비율은 가장 싼 적 1기 비용 이내 오차를 목표
- Prelude 시작 전후에 총 예산 누적량이 증가하지 않아야 함

### 5.6 패킷 제약

현재 `role_limits`를 유지하되 다음 제약을 데이터로 표현한다.

- `HEAVY`, `DISABLE`, `ON_HIT_SPEED + DEATH_BUFF` 과밀 상한
- 강철 골렘 패킷당 최대 1기 및 `rare_spawn_cooldown`
- 서큐버스 Tier별 1/2/3기 상한
- 기병 Tier 1 최소 3기, Tier 상승 시 대열/웨이브 강화
- 입교 희망자 Tier 1 최소 4기, 두 웨이브 그룹 분리
- Tier 1에서 망령·강철 골렘과 팩션 고유 적의 복잡 조합 금지

## 6. 단계별 개선 계획

### M0 — 계약·이관 경계 동결 `P0 / S / 완료`

작업:

- 공용 7종 ID와 팩션 5종 영문 ID 확정
- 18개 구형 ID의 활성 풀 퇴역 목록과 외부 팩 호환 정책 문서화

## 10. 비모바일 완료 정의

다음이 모두 만족될 때 v0.15 비모바일 증분을 완료로 판정한다.

- 활성 적 카탈로그가 공용 7종 + 팩션 5종이고 구형 18종 행동 적이 자동 풀에 없음
- 공용 7종과 팩션 5종의 고유 행동·사망·그룹·대열 계약이 자동 테스트를 통과
- 세 Prelude가 다음 보스 진영만 예고하고 보스 등장 즉시 종료
- Prelude가 기존 Base/Bonus 예산을 대체하며 총예산을 추가하지 않음
- 패킷의 HEAVY/DISABLE/가속/희귀/대열 상한이 데이터와 런타임에서 일치
- 새 12종 자산·도감·HUD·결과/감사 메트릭의 누락과 콘셉트 폴백 0
- 전체 스모크와 5후보×3시드×600초 기술 게이트 통과
- 1×/2×/3× 결정성 지문 일치와 데스크톱 Forward Mobile 성능 예산 통과
- v0.14에서 이월한 성장·편대·Bonus XP 항목이 새 기준선으로 승인되거나 명시적 후속 A/B로 남음

모바일 실기기·배포는 사용자 재개 지시 전까지 별도 미완료 게이트다.
