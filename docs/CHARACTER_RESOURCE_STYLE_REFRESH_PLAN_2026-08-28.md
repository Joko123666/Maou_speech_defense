# v0.19 캐릭터 리소스 스타일 갱신 계획

- 기준일: 2026-08-28
- 기획 기준: `godot_formation_defense_gdd_v0_19.md`
- 참조 이미지: `reference/char_001.png` ~ `reference/char_013.png`
- 활성 프로필: `res://data/concepts/demon_election_vertical_slice.tres`
- 활성 에셋 카탈로그: `res://data/concepts/demon_election_assets.tres`
- 문서 성격: 참조 이미지의 시각 언어를 v0.19 기준에 맞게 정제하고, 현재 런타임 리소스를 안전하게 이관하기 위한 실행 계획
- 현재 상태: M3-D 친위대 5종과 프롬프트 토큰 정리까지 완료해 M3 캐릭터 스테이징 세트를 완성함. 활성 이미지·데이터는 아직 변경하지 않음

## 1. 결론

`char_001~013`은 v0.19이 요구하는 **정사각형 프레이밍, 데포르메, 굵은 외곽선, 밝은 카툰 톤, 강한 실루엣**의 좋은 기준점이다. 특히 13개 모두 1254×1254 정사각형이고, 역할을 보여 주는 무기와 포즈가 크며, 대부분 아군 기준 우향 구도가 명확하다.

다만 원본은 모두 불투명 RGB 배경을 포함하므로 현재 프로젝트의 투명 전신·전투 SD 자산을 그대로 대체할 수 없다. 일부 이미지는 v0.19 팩션색과도 어긋난다. 따라서 다음 원칙으로 갱신한다.

1. 참조 이미지는 **정체성·실루엣·포즈의 기준**으로 사용하고, 단순 배경 제거본을 완성품으로 사용하지 않는다.
2. 게임플레이와 세이브가 참조하는 안정 ID는 유지하고 이미지·표현 메타데이터만 교체한다.
3. 팩션 팔레트와 문양을 먼저 확정한 뒤 캐릭터, 적, 이펙트, 카드 프레임을 같은 토큰으로 갱신한다.
4. 작업 중인 자산은 별도 검수 카탈로그에서 확인하고, 한 카테고리가 완성되기 전에는 활성 카탈로그에 부분 반영하지 않는다.
5. 모바일 실전 크기 48px·64px·96px에서 읽히는지가 원본 확대 품질보다 우선한다.

## 2. 확인한 v0.19 스타일 계약

### 공통 표현

- 비비드 카툰, 두꺼운 외곽선, 데포르메, 플랫 컬러링, 밝은 캐주얼 톤
- 그림자와 질감보다 큰 색면과 즉시 읽히는 실루엣 우선
- 인물·병력·초상은 정사각형 안에서 핵심 얼굴, 무기, 역할이 읽혀야 함
- 공격·피격·넉백·처형·환혹은 강한 키포즈와 과장된 표정으로 표현
- 일반 병력은 단순, 친위대는 더 화려, 후보는 가장 강한 장식성과 존재감을 가짐

### 방향과 진영 구분

- 수비측 후보·심복·친위대·일반 병력: 우향, 굵은 외곽선
- 적측: 좌향, 수비측보다 상대적으로 얇은 외곽선
- 수비측 이미지를 적에게 파생할 때 표정·눈·장식색·이펙트·무기·추가 실루엣 중 최소 1개, 승인 기준으로 2개 이상 변경
- 색상만으로 진영이나 상태를 전달하지 않고 문양·아이콘·움직임을 함께 사용

### 팩션 토큰

| 마왕군 / 파르태손 | 흑·무채색, 제한된 금속 보조색 | 검과 방패 | 전통, 규율, 왕가 문장, 군기, 뿔 투구 |

| 심연 / 카스하 | 녹색, 어두운 심연 보조색 | 촉수와 눈 | 촉수, 눈알, 균열, 점액, 심연 기둥 |

## 3. 현재 프로젝트와의 차이

### 3.1 참조 이미지는 드롭인 리소스가 아니다

- 13개 참조 이미지는 모두 1254×1254 `Format24bppRgb`이며 알파 채널이 없다.
- 현재 일반 병력·친위대·전투 SD·팩션 적은 투명 컷아웃을 사용한다.
- 전투 SD 계약은 정확히 512×512 RGBA와 네 모서리 투명을 요구한다.
- 친위대 계약은 1024px 이상, 투명 모서리, 전용 자산을 요구한다.
- 따라서 참조 이미지에서 배경과 바닥 그림자를 분리하고, 팩션 팔레트·선 굵기·세부 밀도를 다시 조정한 투명 마스터가 필요하다.

### 3.2 기존 자산도 스타일 편차가 있다

- 후보·심복 초상 10개는 512×512이지만 사실적 2.5D 렌더링과 강한 광택·음영 비중이 높아 v0.19의 플랫 카툰 기준과 거리가 있다.
- 일반 병력은 데포르메와 투명 컷아웃을 갖췄지만 장비 세부·광택·그라데이션이 많은 표본이 있어 작은 화면에서 형태가 뭉칠 수 있다.
- 후보·심복 전투 SD는 512×512 RGBA 계약을 충족하나, 새 참조 이미지의 더 단순하고 과장된 형태 언어와 통일 검수가 필요하다.
- 현재 후보·심복 SD는 아군과 공식 난입 보스가 같은 텍스처를 사용하며 적 렌더러가 이를 좌우반전하지 않는다. v0.19의 아군 우향/적 좌향 계약을 완전히 만족하지 못한다.

### 3.3 활성 팩션 데이터가 v0.19 목표 토큰으로 이관되지 않았다

현재 `demon_election_campaign_v0_8.tres`는 파르태손 적/금, 카스하 남청/청록, 이레라이 녹/연두를 사용한다. marker도 `crown`, `star`, `abyss`, `spirit`, `judgment`다. v0.19의 흑/무채색·마젠타·녹색·연청색·적색과 검방패·하트·촉수눈·해골오라·낫피 계약으로 아직 이관되지 않았다.

자산만 교체하면 HUD, 적 진영 마커, 보스 경고, 카드 프레임과 색 의미가 갈라진다. 팩션 데이터·문양·마커를 리소스 교체와 같은 릴리스 단위로 묶어야 한다.

### 3.4 유지해야 할 현재 런타임 계약

- 활성 자산 감사: 68개 활성 콘텐츠 요청, 67개 전용 자산, 승인된 보스 별칭 1개, 누락 0
- 일반 병력 안정 ID: `rapid`, `area`, `pierce`, `slow`, `knockback`, `execute`, `mark`, `chain`, `rubber_golem`
- 후보·심복·친위대·적의 기존 `StringName` ID와 세이브 참조
- 후보·심복 전투 SD 10개 각각 512×512 RGBA, 투명 모서리
- 일반 병력 전신과 얼굴 아이콘 각각 9개 전용 자산
- 친위대 6종 각각 고해상도 전용 투명 자산
- 외부 콘셉트 팩을 위한 구형 코어·커서·emblem·marker 호환 경계

## 5. 제작 사양

### 5.1 공통 마스터

- 작업 마스터: 1254×1254 이상, 정사각형, 무손실 RGBA
- 배경·바닥 그림자·캐릭터·무기·이펙트를 분리 가능한 상태로 보관
- 캐릭터 외곽 안전 여백: 캔버스 각 변의 최소 7%, 긴 무기와 채찍은 최소 4%
- 몸통의 주색면은 3~5개, 재질별 명암 단계는 기본 2단계, 핵심 금속·점액만 제한적 하이라이트 허용
- 외곽선은 캔버스 축소 후에도 끊기지 않는 한 덩어리로 유지하고 내부선은 외곽선보다 얇게 설정
- 텍스트, 워터마크, 배경 그라데이션, 바닥 그림자를 전신 컷아웃에 굽지 않음

### 5.2 런타임 파생 규격

| 용도 | 권장 출력 | 배경/방향 | 구성 규칙 |
|---|---|---|---|
| 일반 병력 전신 | 1254×1254 RGBA | 투명, 우향 | 단순 장식, 무기와 역할 우선 |
| 일반 병력 얼굴 아이콘 | 512px 이상 RGBA | 투명 또는 공통 아이콘 바탕 | 전신의 단순 크롭이 아니라 얼굴·무기 단서 재배치 |
| 친위대 전신 | 1254×1254 RGBA | 투명, 우향 | 일반 병력보다 한 단계 화려, 후보 문양 노출 |
| 후보·심복 초상 | 512×512 RGB/RGBA | 통일된 팩션 비네트 허용 | 얼굴 60~72%, 같은 광원·카메라·선 굵기 |
| 후보·심복 아군 SD | 512×512 RGBA | 투명, 우향 | 네 모서리 알파 0, 전장 키포즈 강조 |
| 공식 난입 SD | 512×512 RGBA | 투명, 좌향 | 중간 외곽선, 적대 표정·장식색·이펙트 중 2개 이상 변경 |
| 공용·팩션 적 | 512×512 RGBA | 투명, 좌향 | 공용은 중립색, 팩션 적은 문양과 대표색 동시 사용 |

Godot `.import` 파일은 직접 편집하지 않는다. PNG/SVG 원본을 교체한 뒤 에디터 재임포트로 현재 `compress/mode=0`, `mipmaps/generate=false`, `fix_alpha_border=true` 기준을 재검증한다.

### 5.3 장식성 등급


## 9. 권장 첫 실행 묶음

다음 개선 작업은 M0과 M1만 수행하는 것이 안전하다.

1. 13개 참조 매핑과 세 개의 조건부 모티프를 확정한다.
2. v0.19 팩션 팔레트·문양 토큰을 수치로 고정한다.
3. `char_001`, `char_005`, `char_011`, `char_012`, `char_013`의 투명 파일럿을 제작한다.
4. 실제 전투·선택 카드·도감에서 48/64/96px A/B를 승인한다.
5. 승인된 파일럿에서 스타일 시트를 고정한 뒤 M2 대량 제작으로 넘어간다.

이 순서면 참조 13개를 활용하면서도, 현재의 안정 ID·자산 감사·외부 팩 호환을 깨지 않고 v0.19의 비주얼 언어로 점진적으로 이관할 수 있다.
