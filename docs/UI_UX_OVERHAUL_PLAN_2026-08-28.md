# UI/UX 전체 개편 계획

- 수립일: 2026-08-28 (Asia/Seoul)
- 시각 기준: `reference/UIUX_001.png`, `reference/UIUX_002.png`, `reference/UIUX_003.png`
- 구현 기준: 현재 Godot 4.7 프로젝트, 1280×720 가로 화면, Mobile 렌더러
- 상태: M0~M6 완료 / M7 반응형·접근성·데스크톱 Forward Mobile 승인 완료, Android 실기기 최종 승인 대기

## 1. 결론

세 참조안의 방향을 현재 프로젝트에 적용하는 것은 적합하다. 특히 전투 중 중앙 시야 보존, 아이콘 중심의 주변 HUD, 선택 카드의 명확한 정보 우선순위, 터치로 여는 유닛 정보 팝오버는 현재 UI의 높은 텍스트 밀도와 스타일 분산을 직접 개선한다.

다만 참조 이미지는 **시각·상호작용 방향**이며 GDD나 런타임 데이터의 권위가 아니다. 화면에 그려진 실시간 기여 순위, 임의 능력치, 임의 상태와 문구를 근거 없이 새 게임 기능으로 만들지 않는다. 현재 v0.19의 안정 ID, 성장·아티팩트·보상 큐, 저장·체크포인트, 전투 판정은 그대로 유지하고 표현 계층을 단계적으로 교체한다.

권장 구현 순서는 다음과 같다.

1. 테마 토큰과 공용 UI 컴포넌트
2. 레벨업·아티팩트·편대 선택 카드 통합
3. 전투 HUD 재배치
4. 유닛 정보 팝오버
5. 메뉴·출격 준비·상점·업적·도감·결과·일시정지 통일
6. 안전영역·접근성·실기기 검증

## 2. 참조안 해석

| 참조 | 핵심 의도 | 프로젝트 적용 | 그대로 복제하지 않을 항목 |
|---|---|---|---|
| `UIUX_001` | 상단 핵심 상태, 좌측 정보 레일, 우측 스폰 레일, 중앙 전장 시야, 의전·축제 분위기 | 전투 HUD의 정보 위계와 주변부 배치, 크림/보라/금색 왕실 선거 테마 | 이미지 속 임의 수치·실시간 기여 순위·전장 크기 |
| `UIUX_002` | 3장 카드의 아이콘 → 제목 → 핵심 효과 → 태그 → 설명 → 시너지 → 선택 순서 | 일반 성장·특화·편대·상태·초과성장·아티팩트의 공용 카드 구조 | 카드마다 별도 중첩 버튼을 두는 구조, 존재하지 않는 시너지 데이터 |
| `UIUX_003` | 선택 대상 근처의 정보 팝오버, 역할/진영 색, 핵심 능력치와 상태 분리 | 후보·일반 수비병력부터 시작하는 터치 고정 팝오버, 이후 심복·적·보스 확장 | 현재 런타임에서 조회할 수 없는 능력치, 항상 표시되는 대형 상세창 |

### 채택할 시각 언어

- 바탕은 따뜻한 양피지·크림, 외곽과 주요 텍스트는 짙은 보라색을 사용한다.
- 금색은 선거·통치·희귀 보상, 빨강/초록/파랑은 POWER/SPEED/RANGE 의미를 유지한다.
- 후보·심복·아군·적·보스는 색뿐 아니라 문양, 아이콘 실루엣, 라벨을 함께 사용한다.
- 둥근 패널, 굵은 외곽선, 장식 모서리로 마계 왕실 선거 분위기를 만든다.
- 전투 중에는 아이콘과 짧은 수치가 우선이고, 긴 설명은 상세 팝오버나 별도 화면에서 제공한다.

### 채택하지 않을 방식

- 참조 PNG를 잘라 실제 패널·버튼 자산으로 사용하지 않는다.
- 장식 군중과 깃발이 전투 판정 영역이나 터치 영역을 가리지 않게 한다.
- 색만으로 세력, 희귀도, 상태, 선택 가능 여부를 구분하지 않는다.
- 기존 GDD에 없는 랭킹·스폰 조작·스탯을 UI를 위해 새 규칙으로 만들지 않는다.

## 3. 현재 UI 감사 결과

| 영역 | 현재 구현 | 확인된 개선점 |
|---|---|---|
| 화면 기준 | `project.godot`의 1280×720, `canvas_items`, `expand` | 16:9만이 아니라 긴 가로비와 OS 안전영역을 검증해야 함 |
| 전투 HUD | `scenes/ui/hud.tscn`, `scripts/ui/hud.gd`의 상단 전폭 바·효과 패널·하단 설명 | 정보가 상단에 연속 배치되어 중요도 구분이 약하고 전투 중 긴 문구 비중이 큼 |
| 선택 화면 | `scenes/ui/level_up_panel.tscn`, `scripts/ui/level_up_panel.gd`의 3개 대형 Button | 기능은 충분하지만 큰 원형 아이콘, 태그, 핵심 효과, 시너지/보조 설명의 구조가 분리되지 않음 |
| 아티팩트 교체 | `artifact_resolution_panel.tscn/.gd`의 6개 텍스트 버튼 | 카드 계층과 비교 규칙을 공용 컴포넌트로 통합할 필요가 있음 |
| 메뉴·허브 | `main_menu.tscn/.gd`의 타이틀·출격·상점·업적·도감 페이지 | 화면마다 직접 지정한 색·여백·스타일이 많고 왕실 선거 테마가 배경에 비해 패널에서 약함 |
| 도감·업적·준비 | 여러 스크립트가 런타임에 Control과 `StyleBoxFlat`을 직접 생성 | 테마 변경 비용이 높고 같은 컴포넌트의 상태 표현이 분산됨 |
| 전투 정보 조회 | `CombatRangeOverlay`가 후보/일반 수비병력 hit test와 사거리 표시를 제공 | 선택 상태를 HUD에 전달하는 계약과 정보 팝오버는 없음 |
| 모바일 기준선 | 48px 일부 핵심 타깃, 기존 78개·M4 팝오버 2개·M6 결과 상세 1개·동적 관중 3개·전용 타이틀 1개를 합친 Forward Mobile UI 스냅샷 85개 | 실제 Android 안전영역·손가락 오조작·뒤로가기·앱 복귀는 미검증 |
| 글꼴 | 대부분 `ThemeDB.fallback_font` 또는 기본 UI 글꼴 | 한국어 가독성과 왕실 선거 인상을 함께 만족하는 제품 글꼴 확정 필요 |

현재 화면은 기능과 상태 커버리지가 넓고, 기존 78개 스냅샷이 좋은 회귀 기준선이다. M4 후보·수비병력 팝오버 2개, M6 결과 상세 스크롤 1개, 후속 동적 관중의 스킬·위험·감소 모션 3개와 전용 타이틀 진입 1개를 더해 현재 자동 화면은 85개다. 개편은 기존 상태를 줄이는 작업이 아니라 같은 상태를 더 일관된 컴포넌트로 표현하고 승인된 새 상태를 추가하는 작업이어야 한다.

## 4. 개편 목표와 비목표

### 목표

- 전투 화면의 중앙 4×6 보드와 적 이동 경로를 가장 높은 시각 우선순위로 유지한다.
- 1초 안에 체력, 시간, 보스, 레벨/XP, 공약 충전, 배속을 읽을 수 있게 한다.
- 성장 카드에서 이름과 실제 수치 변화가 설명보다 먼저 보이게 한다.
- 터치 한 번으로 선택 대상의 역할, 핵심 수치, 상태를 확인하게 한다.
- 메뉴부터 결과까지 같은 색·타이포·간격·상태 규칙을 사용한다.
- 최소 48px 터치 타깃, 안전영역, 키보드·마우스·터치 포커스를 같은 컴포넌트에서 보장한다.
- 기존 78개 화면 상태와 게임 흐름의 기능 회귀를 막는다.

### 비목표

- v0.19 전투 밸런스, RNG, 카드 적격성, 저장 schema, 캠페인 해금 규칙 변경
- 참조 이미지의 임의 콘텐츠를 새 기능으로 구현
- 첫 단계에서 `Battlefield` 좌표·4×6 보드·공격 범위 계산 변경
- 제품 글꼴·아이콘·장식 아트의 라이선스 승인 없이 최종 자산으로 동결

## 5. 디자인 시스템 초안

아래 값은 구현 시작점이며 실제 화면 대비 감사 후 확정한다.

### 색 토큰

| 역할 | 초안 | 용도 |
|---|---|---|
| `surface/parchment` | `#F3E6CF` | 카드·주요 정보 패널 |
| `surface/parchment-muted` | `#E4D2B5` | 보조 패널·비활성 표면 |
| `ink/royal` | `#39234F` | 외곽선·주요 텍스트·아이콘 |
| `ink/deep` | `#20162E` | 전투 HUD 어두운 배경·강한 대비 |
| `accent/gold` | `#D8AE48` | 선거·통치·희귀·보상 |
| `axis/power` | `#D95353` | POWER/위력 |
| `axis/speed` | `#43A867` | SPEED/속도 |
| `axis/range` | `#3F82C8` | RANGE/범위 |
| `faction/ally` | 파랑 계열 | 일반 아군 |
| `faction/retainer` | 초록 계열 | 심복 |
| `faction/boss` | 보라 계열 | 보스·정예 |
| `faction/enemy` | 빨강 계열 | 일반 적 |

색 토큰은 `ConceptService`의 후보·진영 강조색을 덮어쓰지 않고, 공통 표면과 의미 축을 제공한다. 모든 의미 색에는 아이콘 또는 텍스트 라벨을 병행한다.

### 크기 토큰

- 간격: 4 / 8 / 12 / 16 / 24 / 32px
- 본문: 15~17px, 보조: 12~14px, 카드 제목: 21~24px, 화면 제목: 30~36px
- 터치 타깃: 최소 48×48px, 주요 행동 56px 이상
- 아이콘: 24 / 32 / 48 / 64px
- 패널 외곽선: 일반 2px, 선택·희귀·경고 3~4px
- 모서리: 소형 8px, 카드 14px, 모달 18px
- 애니메이션: 상태 전환 160~220ms, 카드 등장 220~320ms, 감소 모션 옵션에서 즉시 또는 80ms 이하

### 상태 규칙

- 기본, hover, pressed, focus, disabled, selected, warning, locked를 공용으로 정의한다.
- 포커스는 색 변화만이 아니라 3px 외곽선과 짧은 라벨/아이콘 변화로 표시한다.
- 비활성은 투명도만 낮추지 말고 잠금 아이콘과 이유 문구를 함께 제공한다.
- 수치 증가는 `이전 → 이후`, trade-off는 이득과 손해를 분리된 행으로 표현한다.

## 6. 화면군별 목표 구조

### 6.1 전투 HUD — `UIUX_001`, `UIUX_003`

1280×720에서 다음 계층을 사용한다.

| 구역 | 표시 정보 | 동작 |
|---|---|---|
| 좌상단 압축 배지 | 도전 단계, 칙령, 다음 Prelude | 탭하면 런 규칙 요약 팝오버 |
| 상단 중앙 | 남은 시간, 보스 이름/체력, 경고 | 전투 중 항상 가시; 보스 없을 때 시간 중심 |
| 상단 우측 | 공약, 배속, 사거리, 일시정지 | 모두 48px 이상, 아이콘+짧은 라벨 |
| 상단 보조 미터 | 지지도 또는 XP 중 현재 핵심 진행 | XP는 레벨과 결합, 지지도는 실제 런 데이터가 있을 때만 표시 |
| 좌측 주변 레일 | 상태 강화, 아티팩트 6칸, 후보/심복 식별 | 아이콘 우선, 탭하면 상세; 긴 빌드 문구 제거 |
| 중앙 전장 | 후보·심복·병력·적·투사체 | 고정 HUD가 전장 판정 영역을 가리지 않음 |
| 우측 스폰 프레임 | 경고 행, 다음 진영/Tier, 등장 방향 | 현재 스폰 좌표를 시각적으로 프레이밍하며 입력을 막지 않음 |
| 하단 | 접힌 조작 도움말, 일시 알림 | 기본은 접힘; 튜토리얼과 접근성 모드에서만 확장 |

중요 제약: `Battlefield.get_column_spacing()`이 공격 범위 계산에 사용된다. 따라서 HUD 개편을 위해 `horizontal_margin`이나 전장 폭을 먼저 바꾸지 않는다. 참조안의 레일은 현재 주변 여백과 비차단 오버레이로 구현한다. 전장 폭 변경이 필요하면 별도 전투 계약과 1×/2×/3×·장기 밸런스 재감사를 선행한다.

현재 화면의 실시간 기여 순위는 권위 데이터가 없으므로 P2 후보 기능으로 둔다. 결과 화면의 기여 요약을 전투 중 순위처럼 재사용하지 않는다.

### 6.2 선택 카드 — `UIUX_002`

일반 성장, 후보/심복, 상태, 특화, 편대, 초과성장, 아티팩트를 하나의 카드 골격으로 통일한다.

카드 내부 우선순위:

1. 큰 원형 아이콘 또는 병력/편대 미리보기
2. 카드 이름과 레벨/희귀도
3. 핵심 수치 변화
4. 대상·역할·형태·상태 태그
5. 짧은 설명
6. 시너지 또는 trade-off; 데이터가 없으면 영역 자체를 숨김
7. 선택 affordance와 단축키

전체 카드가 하나의 버튼이어야 한다. 카드 안에 다시 선택 Button을 중첩하지 않고 하단 선택 영역도 부모 카드와 같은 입력을 사용한다. 편대 상세는 보조 버튼 또는 길게 누르기로 열되 선택과 명확히 분리한다.

레이아웃 기준:

- 3열 카드는 동일 폭·동일 높이로 유지한다.
- 핵심 효과는 최소 두 줄을 확보하고 설명보다 강한 대비를 준다.
- POWER/SPEED/RANGE, 후보/심복/친위대, 상태 아이콘은 현재 `UpgradePresentationService`와 `FlatEffectIcon`을 재사용한다.
- 리롤은 화면 하단 중앙의 독립 56px 바 형태로 배치하고 남은 횟수와 비용/제한 이유를 표시한다.
- 1280×720에서 세로 스크롤 없이 핵심 선택이 가능해야 하며, 긴 상세는 별도 팝오버로 보낸다.

### 6.3 유닛 정보 팝오버 — `UIUX_003`

1차 대상은 현재 hit test가 이미 존재하는 후보와 일반 수비병력이다. 2차에서 심복, 적, 보스의 안전한 hit test와 읽기 전용 상태 스냅샷을 추가한다.

표시 항목:

- 초상/아이콘, 이름, 레벨 또는 Tier
- 진영·역할·병종 태그
- 체력, 위력, 방어/저항, 행동속도 또는 실제 권위가 있는 4개 핵심 수치
- 적용 중 특성·특화·상태를 서로 분리한 아이콘 목록
- 처치·기여 수치는 정확한 런타임 귀속이 있을 때만 표시

상호작용:

- 터치: 대상 탭으로 고정, 바깥 탭/닫기/ESC로 해제
- 마우스: hover 미리보기, 클릭으로 고정
- 키보드/패드: 사거리 확인 포커스와 같은 선택 순서를 사용
- 팝오버는 대상의 반대편 사분면을 우선하고 화면·안전영역 안으로 clamp한다.
- 보상 모달, 준비 화면, 일시정지, 결과 화면이 열리면 자동으로 닫는다.

구현 연결점은 `CombatRangeOverlay`의 내부 선택을 직접 읽는 방식이 아니라 `inspection_changed(snapshot)` 같은 읽기 전용 신호와 presenter를 두는 방식이 적합하다. 사거리 원과 정보 패널이 같은 선택 상태를 사용하면 터치 중복과 서로 다른 대상 표시를 막을 수 있다.

### 6.4 메인 메뉴·출격 허브

- 타이틀 화면은 현재 좌측 서사/우측 명령 구조를 유지하되 크림 패널과 보라 외곽, 금색 상태 배지로 참조안과 통일한다.
- 출격 설정은 후보 → 심복 → 도전/칙령 → 확인 순서를 단계형으로 보이게 한다.
- 후보·심복 카드는 초상, 이름, 역할, 핵심 특성, 잠금/해금 이유를 같은 위치에 배치한다.
- 상점·업적·도감은 같은 `PageShell`, 헤더, 뒤로가기, 탭, 목록/상세 골격을 공유한다.
- 도감의 6분류와 현재 발견/잠금 의미는 유지하며, 목록은 간결하게 하고 상세 패널에 역할 태그와 축 아이콘을 집중한다.

### 6.5 준비·교체·일시정지·결과

- 편대 준비는 보드와 설명을 동일 위계로 경쟁시키지 않고 보드 60%, 선택 설명/확정 40% 구조로 정리한다.
- 아티팩트 6칸 교체는 신규 카드와 기존 6칸을 동일 카드 문법으로 비교하며 이득/손해를 분리한다.
- 일시정지는 같은 `ModalShell`을 사용하고 계속/옵션/타이틀의 위험도를 색과 위치로 구분한다.
- 결과 화면은 진행 타임라인, 선거 자금, 지지도/통치, 빌드·아티팩트 기여의 순서로 재구성한다. 전투 중 존재하지 않는 정보는 결과에서만 유지한다.

구현 상태: **완료**. 전용 성채 배경의 타이틀 진입 화면과 유세 본부 허브를 분리하고, 허브에는 현재 후보 초상·수석 심복·지지도·승인도와 네 메뉴 행동을 배치했습니다. 출격 설정·상점·업적·도감은 실제 `PageShell` 인스턴스와 양피지/왕실 보라/금색 공용 상태를 사용하며, 하위 메뉴에서는 중복 전역 브랜드 바를 접어 720p 내용 영역을 확보합니다. 출격은 후보→심복→도전·칙령 순서를 고정하고 잠긴 후보·심복의 이전 정체성 최초 승리 조건, Challenge 최초 완주 조건, 당선 전 칙령 잠금 이유를 텍스트로 표시합니다. 긴 출격 내용은 내부 스크롤로 보내고 시작 버튼은 하단에 고정했습니다. 상점 카드는 구매 가능/자금 부족/구매 완료를, 업적과 도감은 공용 탭·상태 배지와 분류별 선택/스크롤 상태를 보존합니다. 페이지 뒤로가기는 유세 본부에서 진입한 버튼으로 포커스 의도를 반환하며 `UiUxM5MetaPagesContractTest`가 배경 전환·중복 chrome 접기·탐색 전후 세이브 동일성까지 검사합니다. 85개 Forward Mobile 화면을 생성해 대표 메뉴 화면군을 승인했습니다.

작업:

- 타이틀, 출격 설정, 상점, 업적, 도감에 `PageShell`과 공용 버튼/탭/카드를 적용한다.
- 후보·심복 선택의 잠금, 지지도, 도전 상한, 칙령 설명을 한 카드 위계로 정리한다.
- 도감 목록/상세와 업적 카드의 스크롤, 포커스 복귀, 상태 배지를 통일한다.

완료 조건:

- 현재 해금·구매·발견·Challenge 동작과 저장 결과 동일
- 각 페이지의 뒤로가기·포커스 복귀·스크롤이 터치/키보드에서 일치
- 긴 잠금 이유와 미발견 상태가 잘리지 않음

### M6 — 준비·일시정지·결과 마감

구현 상태: **완료**. 편대 준비·일반 편대 배치, 6칸 아티팩트 교체, 일시정지·전투 옵션, 승리·패배 결과를 실제 `ModalShell` 본문/고정 푸터에 이관했습니다. 공용 모달은 bounded 스크롤, 초기 포커스와 이전 포커스 복귀를 제공하며 편대 포기·아티팩트 포기·출격 포기는 위험색과 명시적 확인 절차를 사용합니다. 결과는 진행→보상→지지도/통치→빌드/기여의 4단계로 재배치하고 긴 상세만 스크롤되도록 이동 버튼을 푸터에 고정했습니다. 기존 교체/포기·resume/quit·restart/menu 신호와 UI 밖 보상 큐·체크포인트/정산 권위를 유지하며 `UiUxM6ModalFlowsContractTest`와 현재 85개 Forward Mobile 화면으로 검증합니다.

작업:

- 편대 준비, 아티팩트 교체, 일시정지, 옵션, 승리/패배 결과를 공용 모달 체계로 이관한다.
- 결과의 진행·보상·지지도·통치·빌드 기여를 단계형으로 재배치한다.
- 위험 행동은 위치, 색, 확인 절차를 통일한다.

완료 조건:

- 보상 큐 정지/재개, 교체/포기, 재시작/타이틀 신호 회귀 없음

### M7 — 반응형·접근성·성능 승인

구현 상태: **자동·데스크톱 Forward Mobile 범위 완료 / Android 실기기 승인 대기 (2026-08-28)**. 최소 지원 가로 화면은 프로젝트 기준선과 같은 1280×720으로 확정하고 1600×720·1920×1080 및 방어적 960×540 축소 표본을 함께 검사합니다. `PageShell`, `ModalShell`, HUD가 런타임 safe rect와 뷰포트 변경을 자동 반영하며, 큰 모달은 가용 영역으로 제한되고 HUD는 좁은 논리 뷰포트에서 compact 배치를 사용합니다. 공용 포커스 순환·읽기 가능한 버튼 이름, 양피지 본문/금색 의미 텍스트 대비 계약, 저장되는 감소 모션 옵션을 추가했습니다. 감소 모션은 카드 등장·HUD 강조·결과 카운터·타임라인과 화면 흔들림을 즉시 억제합니다. Page/Modal/HUD는 이벤트 기반 갱신만 사용합니다.

`UiUxM7ResponsiveAccessibilityContractTest`와 전체 스모크, 1280×720·1600×720 실제 Forward Mobile 렌더, 1920×1080 레이아웃 계약을 통과했습니다. 960×540은 축소 시 잘림 방어 확인용이며 48px 물리 터치 타깃을 보장하는 지원 해상도로 승인하지 않습니다. 3×·180Hz 120초 실제 창 감사는 평균 5.574ms, 최악 16.667ms, 33ms 초과 0%로 성능 예산을 통과했습니다. 연결 Android 기기가 없어 노치/제스처 safe inset, 실제 터치·뒤로가기, 중단/복귀, 발열·메모리·배터리는 최종 승인하지 않았습니다.

작업:

- 1280×720, 1600×720, 1920×1080, 최소 지원 가로 해상도에서 레이아웃을 검증한다.
- 실제 또는 모의 safe inset을 모든 page/modal/HUD shell에 적용한다.
- 본문 4.5:1, 큰 글자·비텍스트 경계 3:1을 목표로 대비를 점검한다.
- 감소 모션, 흔들림, 플래시, 사운드 옵션과 포커스/스크린리더용 이름을 정리한다.
- UI 갱신이 매 프레임 불필요한 스타일·노드 재생성을 만들지 않게 한다.

완료 조건:

- 48px 미만 주요 터치 타깃 0개
- 키보드·패드 포커스 막힘 0개, 터치 뒤로가기 흐름 승인
- Forward Mobile 3× 성능 기준선 회귀 없음
- Android 대표 실기기의 안전영역·입력·중단/복귀 승인

## 12. 최종 완료 정의

다음 조건을 모두 만족하면 UI 전체 개편 완료로 판정한다.

- 세 참조안의 핵심인 주변부 전투 HUD, 계층형 3택 카드, 대상 정보 팝오버가 실제 런에 연결됨
- 메뉴부터 결과까지 공용 Theme과 컴포넌트를 사용하며 화면별 임의 스타일 책임이 예외 목록 밖에 남지 않음
- 기존 78개 상태가 모두 보존되고 신규 팝오버·안전영역·긴 화면비 상태가 자동 스냅샷에 추가됨
- 현재 v0.19의 전투·성장·아티팩트·저장·정산·튜토리얼 계약과 1×/2×/3× 지문이 유지됨
- 48px 터치, 대비, 포커스, 감소 모션, Android 뒤로가기와 safe inset이 대표 실기기에서 승인됨
- 3× Forward Mobile 성능과 대표 Android 실기기 프레임·발열 기준선이 개편 전보다 악화되지 않음

M0 기준선 manifest부터 M6 준비·교체·일시정지·옵션·결과까지 구현을 마쳤고, M7의 다중 해상도·모의 safe inset·대비·포커스·감소 모션·데스크톱 Forward Mobile 3× 승인도 완료했습니다. 다음 자동 구현 시작점은 M8 전체 회귀와 직접 스타일 잔여 정리이며, M7/M8의 최종 완료에는 Android 대표 실기기 승인이 계속 필요합니다.
