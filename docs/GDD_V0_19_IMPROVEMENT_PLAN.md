# Formation Defense GDD v0.19 개선 계획

- 기준일: 2026-08-28
- 기획 기준: `godot_formation_defense_gdd_v0_19.md` (6,338행)
- 구현 기준선: v0.19 M0~M8 구현·비모바일 통합 밸런스 승인 상태의 실제 프로젝트
- 문서 성격: v0.17~v0.19 증분을 현재 코드에 안전하게 이관하는 실행 계획
- 모바일 실기 검증: 2026-08-28 재개. 기술 대체 검증 완료, 연결 기기·릴리스 서명 부재로 최종 승인 보류

## 1. 결론

프로젝트를 v0.19 방향으로 개선하는 것은 맞다. 다만 GDD의 구현 우선순위를 처음부터 다시 수행하면 이미 완료된 4×6 보드, 후보·심복·친위대, 9종 수비병력, 상태이상, 적 카탈로그와 SpawnDirector를 중복 재구현하게 된다.

실제 증분은 다음 세 축이다.

1. **v0.17 온보딩·메타 진행**: 60초 튜토리얼, 후보/심복 독립 순차 해금, Challenge 0→10 순차 해금, 즉시 구매 가능한 5종 병력 상점, 용어·전투 규칙 도감.
2. **v0.18 공통 성능 언어·초과성장**: 9종의 POWER/SPEED/RANGE 의미 매핑과 후보·심복 정규 성장 완료 뒤 저효율 반복 성장.
3. **v0.19 아티팩트**: 기존 전역 강화 카드를 제거하고 2분 주기 운반 정예의 확정 3택, 6칸 런 내 인벤토리, 교체/포기, 결과·메트릭·감사를 추가.

권장 순서는 다음과 같다.

```text
M0 문서·호환 결정과 v0.16 무아티팩트 기준선 동결
→ M1 메타 저장·후보/심복/Challenge 순차 해금
→ M2 60초 튜토리얼 수직 절편
→ M3 상점·도감·허브 온보딩 정리
→ M4 POWER/SPEED/RANGE 데이터·런타임 매핑
→ M5 후보/심복 초과성장
→ M6 ArtifactData·인벤토리·효과 적용 기반
→ M7 제안·교체/포기 UI·HUD(초기 저확률 경로, 이후 운반 정예 3택으로 대체)
→ M8 결과·체크포인트·메트릭·장기 밸런스 승인
→ M9 모바일·배포 기술 검증 부분 완료, 실기기·릴리스 승인 대기
```

## 3. 먼저 확정할 충돌과 해석

### 3.1 활성 프로필

`formation_defense.tres`는 선거 캠페인 데이터가 없는 범용/호환 프로필이다. v0.19의 후보·심복·유세 판타지를 실제로 제공하는 프로필은 `demon_election_vertical_slice.tres`이므로 다음처럼 처리한다.

- 활성 런타임 프로필은 `demon_election_vertical_slice.tres` 유지.
- `formation_defense.tres`는 외부 팩·범용 계약 테스트용 호환 프로필 유지.
- GDD 머리말의 활성 콘셉트 경로만 실제 설정에 맞게 정정.

### 3.2 첫 레벨업 병력 세트

v0.19는 보장 여부를 미확정으로 되돌렸지만, 현재 프로젝트와 v0.16 공유 결정은 첫 레벨업에서 일반 병력 세트 1장 보장을 확정 계약으로 사용한다. 명시적인 새 사용자 결정 전까지 현재 계약을 유지한다.

### 3.3 병력 상점 발견 조건

v0.19는 후속 5종을 모두 확인하고 자금만 있으면 원하는 순서로 구매하도록 요구한다. 현재의 업적→상품 발견→구매 흐름은 병력 구매에 대해서는 폐기한다.

- 5개 병력 상품은 처음부터 `DISCOVERED` 또는 동등한 구매 가능 상태로 표시.
- 기존 발견 업적은 보너스 유세 자금·칭호·도감 기록으로 전환하고 구매 전제에서 분리.
- 이미 발견/구매한 세이브는 손실 없이 유지.

### 3.4 전역 강화와 3축

POWER/SPEED/RANGE는 새 전역 레벨 세 개가 아니다. 병력별 핵심 수치를 설명하고 아티팩트·특화가 같은 의미로 적용되게 하는 데이터 언어다. 따라서 기존 `global_upgrade_level`을 세 레벨로 기계적으로 분할하지 않는다.

- 새 제안 풀에서는 `global_upgrade` 제거.
- 구형 결과·테스트·세이브를 읽기 위한 레거시 필드는 한 이관 주기 유지.
- 아티팩트가 없는 런의 기본 수치는 전역 강화가 없다는 전제로 다시 기준화.

### 3.5 아티팩트 역할

아티팩트는 저점 보정이 아니라 고점 확장이다. Base-only 평균 빌드가 아티팩트 없이도 표준 런에 도전 가능한 v0.16 기준선을 먼저 동결하고, 이후 아티팩트를 별도 실험축으로 추가한다.

## 4. 단계별 실행 계획

## M0 — 문서·계약·무아티팩트 기준선 동결

상태: **완료 (2026-08-27, 역사적 실패 대조군)**. 감사 schema v17과 `artifact_mode=disabled`를 동결했고 Godot 파싱·전체 스모크·60초 1×/2×/3× 등가성이 통과했다. 당시 600초 3시드는 평균 생존 374.76초·최종 보스 도전 0/3으로 밸런스 게이트에 실패했으며 `docs/RUNTIME_BALANCE_AUDIT_2026-08-27_V019_M0.md`에 비교 기준으로 보존한다. 이 실패는 M8C의 일반 group 누수·최종전 전 핵 보호·중간 보스 반복 돌파 정책과 재감사에서 해소됐다.

### 작업

- GDD 활성 프로필, 첫 레벨업 보장, 완료된 P0/P1 항목을 실제 구현에 맞게 정정.
- `GDD_V0_16_IMPROVEMENT_PLAN`의 미완료 M3~M6을 v0.19 선행 안정화 게이트로 연결.
- 감사 schema v17, 빌드 정책/RNG revision 2, 1×/2×/3× 등가성 결과를 기준선으로 저장.
- 아티팩트 `disabled` 상태의 평균 빌드×평균 플레이 장기 결과를 이후 비교의 대조군으로 동결.

### 완료 기준

- 이미 구현된 보드·성장·SpawnDirector를 v0.19 작업으로 재작성하지 않는다는 계약 테스트.
- Godot 전체 파싱·스모크·60초 속도 등가성 통과.
- 600초 핵심 3시드 이상 무아티팩트 대조군 저장.

## M1 — 메타 저장과 순차 해금

상태: **완료 (2026-08-27)**. 메타 세이브 v12와 해금 사슬 revision 1을 적용하고, 캠페인 후보/심복 배열 기반의 독립 최초 승리 해금 및 Challenge 0→10 순차 상한을 구현했다. v11 승리 기록·후속 콘텐츠 해금은 보수적으로 복원하며 신규 계정의 미수령 첫 보상은 유지한다. Godot 파싱과 전체 스모크가 통과했고 Forward Mobile 잠금/해금 스냅샷을 직접 확인했다.

### 작업

- 메타 세이브를 v12로 올리고 `candidate_first_clear_ids`, `retainer_first_clear_ids`, 명시적 해금 사슬 revision을 추가.
- 캠페인의 후보/심복 배열 또는 별도 `MetaUnlockSequenceData`를 권위로 사용하고 레거시 Core/Cursor ID로 변환.
- 한 승리에서 후보와 심복 해금을 독립 판정하고 각각 다음 1명만 지급.
- Challenge별 최고 클리어를 `highest_challenge_by_stage`에서 사용하되 선택 상한을 `min(highest_clear + 1, 10)`으로 제한.
- 최초 클리어 전 Challenge 컨트롤 전체 숨김, 이후에만 표시.
- 구형 세이브는 기존 해금·최고 기록을 역행시키지 않도록 보수적으로 이관.

### 완료 기준

- 신규 계정은 파르태손/칸다만 선택 가능.
- 같은 조합 첫 승리에서 다음 후보·다음 심복·Challenge 1이 각각 1회 해금.
- 재승리 중복 지급 없음, 후보/심복 교차 조합도 독립 진행.
- Challenge n 클리어 전 n+1 초과 선택 불가.

## M2 — 60초 튜토리얼 수직 절편

상태: **완료 (2026-08-27)**. `TutorialScenarioData`·`TutorialDirector`·`tutorial_60s`·전용 씬을 추가하고 6단계 학습 흐름을 실제 전투에 연결했다. 메타 세이브 v13의 완료 상태로 최초 메뉴 라우팅을 제어하며 기존 플레이어는 `total_runs > 0`일 때 완료로 이관한다. 튜토리얼은 표준 체크포인트/정산과 Bonus Spawn을 사용하지 않고, 배속·사거리·리롤·무작위 카드·Challenge를 숨긴다. 계약·전용 런타임 스모크·Forward Mobile 1280×720 이동/배치 화면 검증을 통과했다.

### 작업

- `TutorialScenarioData`, `TutorialDirector`, 전용 짧은 스테이지/씬을 추가.
- 파르태손·칸다·고블린 고정, 배속/리롤/특화/랜덤 3택 비활성.
- 이동→고블린 지정 배치→고정 성장 1장→튜토리얼 보스→후보 액티브 순서의 단계 상태 머신 구현.
- 튜토리얼 완료 여부 저장과 최초 허브 진입 라우팅 추가.
- 실제 전투 서비스를 재사용하되 SpawnDirector·보상·메타 정산은 튜토리얼 전용 정책으로 격리.

### 완료 기준

- 약 45~75초 범위에서 여섯 학습 단계 완료.
- 튜토리얼 중 배속·리롤·무관 카드·Challenge가 노출되지 않음.
- 중단 후 재시작과 완료 후 재진입 정책이 명확하고 중복 메타 보상 없음.

## M3 — 허브·상점·도감 온보딩 정리

## M9 — 모바일·배포 승인

상태: **기술 준비 부분 완료 / 최종 승인 보류 (2026-08-28)**. 48px 터치 타깃을 포함한 6칸 HUD·교체 모달 계약, 78개 Forward Mobile UI 스냅샷, 전체 스모크를 통과했다. Android arm64 디버그 APK를 min SDK 24/target SDK 36으로 내보내고 v2/v3 서명, landscape/immersive 설정, 불필요 권한 없음, `tests/*` 제외를 확인했다. 3×/180Hz 실제 창 렌더 감사는 120.02초와 패배 종료 482.53초 모두 평균 약 5.6ms·33ms 초과 0%·성능 게이트 통과였다.

전체 재검증에서도 파싱·전체 스모크·튜토리얼·경제·UI·시작 씬 부팅·60초 1×/2×/3× 등가성이 통과했다. 새 Android 디버그 APK의 구조·v2/v3 서명을 확인했고 494.32초 실제 창 감사도 평균 5.561ms·최악 16.667ms·33ms 초과 0%로 통과했다. Android 릴리스는 키스토어 부재로 실패하며 iOS/Windows 독립 preset은 없다. 상세 빌드 가능 판정은 `docs/FULL_VALIDATION_AUDIT_2026-08-28_V019.md`를 따른다.

연결 Android 기기·에뮬레이터가 없어 설치/첫 실행, 실제 터치·안전영역·뒤로가기, 1×/3× 10분 발열·메모리·배터리·스피커는 미검증이다. 릴리스 키, 제품 패키지 ID·앱 이름·버전·아이콘도 확정되지 않았고 Windows 호스트에서는 iOS 서명·실기기 검증을 수행할 수 없다. 상세 근거와 후속 체크리스트는 `docs/MOBILE_VALIDATION_AUDIT_2026-08-28_V019_M9.md`를 따른다.

## 6. 저장·호환 전략

- 메타 세이브 v12에서 후보/심복 최초 클리어와 해금 사슬 revision, M2의 v13에서 튜토리얼 완료 revision, M3의 v14에서 실제 적 조우 원장을 추가.
- 기존 `unlocked_ids`는 안정 Core/Cursor ID 호환 뷰로 유지.
- 기존 `candidate_clear_records`에서 후보 최초 승리를 복원하고, 심복 기록은 과거 결과에 권위 데이터가 없으면 현재 해금 상태를 보수적으로 보존.
- Challenge 기존 최고 기록은 그대로 인정하되 새 선택 가능 상한을 그 기록+1로 계산.
- `global_upgrade_level`은 새 런에서 생성하지 않고 구형 결과/감사 JSON 해석용으로만 한 버전 유지.
- 아티팩트는 런 내 상태이므로 영구 메타 인벤토리로 저장하지 않는다. 결과·정산 복구 스냅샷에는 최종 보유 목록과 메트릭만 보존.
- 안정 ID `standard_20m`, Core/Cursor/Tower/Formation ID와 기존 상품/업적 ID는 유지.

## 9. 최종 판정

v0.19는 현재 프로젝트에 적용할 수 있으며 방향도 적합하다. 안전한 적용 범위는 기존 전투 기반을 유지한 채 **온보딩/메타 진행 → 공통 성능 언어 → 아티팩트** 순으로 증분 구현하는 것이다. 가장 큰 선행 위험은 아티팩트 자체가 아니라, 기존 전역 강화 제거와 v0.16 무아티팩트 성장선이 동시에 바뀌어 원인을 분리할 수 없게 되는 것이다. 따라서 M0 대조군 동결과 M4의 축 매핑을 건너뛰고 아티팩트 UI부터 만드는 작업은 금지한다.
