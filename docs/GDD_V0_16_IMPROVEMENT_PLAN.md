# Formation Defense GDD v0.16 개선 계획

- 기준일: 2026-08-26
- 기획 기준: `godot_formation_defense_gdd_v0_16.md`
- 구현 기준선: GDD v0.15 M0~M4 완료본
- 문서 성격: v0.16 저점 보장형 밸런스 철학과 아트/디자인 방향을 실제 구현·감사·승인 절차로 전환하는 실행 계획
- 모바일 실기 검증: 2026-08-13 사용자 재개 지시 전까지 보류

## 1. 결론

v0.16의 핵심은 새 전투 시스템을 하나 더 추가하는 것이 아니다. 이미 연결된 후보·심복·친위대·편대·상태·SpawnDirector를 다음 두 기준으로 다시 승인하는 작업이다.

1. **저점 보장형 표준 난이도**: 좋은 빌드는 편하게 이기고, 평균 빌드는 평균 플레이로 이기며, 다소 약한 빌드는 좋은 조작으로 복구할 수 있어야 한다.
2. **통일된 시각 언어**: 아군/적 방향, 외곽선, 실루엣, 팩션 색·심볼, 상태 아이콘을 모바일 화면에서 색상 외 단서까지 포함해 구분해야 한다.

계획 수립 당시 v0.15 M4 구현은 전투 기반을 충분히 제공했지만 이를 v0.16 기준으로 승인할 증거가 부족했다. M0~M2에서 문서 기준선, Prelude 관측성, 빌드·숙련·Bonus 통제 축을 보완했으며, 이제 남은 핵심은 장기 표본으로 Base 성장선과 저점·소프트 카운터를 수렴하는 일이다.

따라서 실행 순서는 다음과 같이 고정한다.

```text
M0 문서·계약 기준선 정정
→ M1 v0.15 관측성·Prelude 표시 완료
→ M2 빌드 강도×플레이 숙련 감사 하네스
→ M3 Base 성장선·저점·소프트 카운터 수렴
→ M4 팩션·상태 시각 언어 데이터 계약
→ M5 활성 자산·UI·전투 가독성 이관
→ M6 통합 비모바일 승인
→ M7 모바일·배포 승인(사용자 재개 후)
```

M1~M3은 수치 밸런스 트랙, M4~M5는 비주얼 트랙이다. M0 뒤 두 트랙의 구현 자체는 병행할 수 있지만, M6 통합 승인 전에는 양쪽 결과를 모두 완료해야 한다.

### 확인한 자산의 의미 판정

- 일반 수비병력은 우측을 향하고 굵은 외곽선을 사용해 v0.16의 아군 방향성과 대체로 일치한다.
- 공용 고블린 적과 이레라이 기병은 좌향 실루엣이 명확하다.
- 지아느 서큐버스와 카스하 심연 피조물은 정면성이 강하고, 주다긴다 입교 희망자는 우향으로 보여 적 좌향 규칙과 일치하지 않는다.
- 현재 자산은 전용 실루엣과 투명도 품질은 좋지만 플랫 컬러보다 광택·세부 음영이 강한 표본이 있다. 전면 폐기보다 모바일 실전 축소 크기에서 읽히는지를 먼저 판정한다.
- 활성 12종은 이미 전용 자산을 가지므로 v0.16의 “아군 자산 좌우반전 재사용 가능” 조항을 이유로 전용 자산을 재사용품으로 되돌리지 않는다. 해당 조항은 신규·외부 콘텐츠의 제작 선택지로만 둔다.

## 4. v0.16 밸런스 승인 모델

### 4.1 빌드 강도 축

감사 하네스가 결과를 미리 조작하지 않도록 각 정책은 동일한 적 시드와 제안 목록을 사용하고 **선택 규칙만** 바꾼다.

| 등급 | 선택 정책 | 의도 |
|---|---|---|
| `strong_synergy` | 후보·심복·칙령·주력 병력·상태·특화를 알려진 연계 태그로 정렬 | 완성된 고점 빌드 |
| `average_coherent` | 현재 빌드 연계와 역할 결손을 균형 있게 선택하되 최적 조합을 강제하지 않음 | 일반 플레이의 중앙값 |
| `weak_coherent` | 낮은 시너지 선택을 우선하지만 배치 가능성과 최소 역할은 유지 | 약하지만 플레이로 복구 가능한 빌드 |
| `tangled` | 역할 중복·낮은 연계를 허용하고 첫 유효 배치를 사용 | 구조적으로 꼬인 빌드 |

빌드 등급은 특정 후보의 고정 이름으로 정의하지 않는다. `category:data_id`, 역할 태그, 상태 적용 수단, 현재 보드 배치 가능성, 실제 선택 로그로 재구성 가능해야 한다.

### 4.2 플레이 숙련 축

| 등급 | 심복 이동 | 후보 액티브 | XP 회수·배치 |
|---|---|---|---|
| `high` | 0.75초 이하 주기로 플레이어에게 보이는 우선 위협을 추적 | 위협 밀도·보스·제어 창을 고려해 사용 | 위험을 감수한 회수, 유효 위치 수와 전투 역할을 고려한 배치 |
| `average` | 1.5~2.0초 주기로 가장 가까운 명확한 위협에 반응 | 준비 후 짧은 지연 안에 사용 | 안전 범위 회수, 현재 빌드 연계/첫 적정 위치 선택 |
| `low` | 드물게 이동하거나 기본 위치 유지 | 장시간 지연·일부 미사용 | 소극적 회수, 첫 유효 위치 선택 |

자동 조작은 숨은 적 데이터, 미래 RNG, 다음 카드 목록을 읽지 않는다. 실제 HUD나 공개 런 상태로 플레이어가 판단할 수 있는 정보만 사용한다.

### 4.3 목표 결과 게이트

초기 수치는 승인 전 조정 가능한 **측정 시작점**이다.

| 셀 | 1차 목표 |
|---|---|
| 강한 빌드 × 평균 플레이 | 승률 90% 이상, 평균 결전 여유가 평균 빌드보다 유의미하게 큼 |
| 평균 빌드 × 평균 플레이 | 승률 70~90%, 후보별 심각한 조기 전멸 없음 |
| 약한 빌드 × 높은 플레이 | 승률 30~70%, 승리 표본은 낮은 핵 체력 또는 긴 최종전으로 “아슬아슬함” 확인 |
| 약한 빌드 × 낮은 플레이 | 평균 빌드보다 명확히 낮은 승률, 패배 가능 유지 |
| 꼬인 빌드 × 평균 이하 플레이 | 패배 가능이 실제로 관측되며 자동 구제하지 않음 |

절대 승률만으로 승인하지 않는다. 평균 생존시간, 최종 보스 진입률, 최종 보스 TTK, 결전 시작/종료 후보 체력, 심복 이동·액티브 기여, CC 유효시간을 함께 본다. 3시드는 방향 확인용이고 최종 판정은 경계 셀마다 후보별 최소 5시드 이상을 사용한다.

### 4.4 Base/Bonus 성장 계약

- 감사에 `bonus_mode=normal|disabled|capped`를 추가한다.
- `disabled`는 Base 스폰·XP만으로 평균 빌드가 최종 보스에 도전 가능한 성장선에 도달하는지 확인하는 통제 실험이다.
- Bonus가 꺼져도 보스 타임라인, Base 예산, 적격 시간은 바꾸지 않는다.
- Bonus XP 비율은 25%를 상한 후보로 유지하되 20~25%를 목표치로 강제하지 않는다. 현재 4.51%가 새 적 카탈로그에서도 충분하면 낮은 비율을 승인할 수 있다.
- 최종 레벨뿐 아니라 `base_experience`, `bonus_experience`, 레벨 도달 시각, 후보/심복/친위대 성장 도달을 분리한다.
- Base-only 실패가 화력 부족인지 XP 회수 실패인지 구분하도록 생성 XP와 회수 XP를 함께 기록한다.

### 4.5 소프트 카운터 계약

- 보스·희귀 적의 둔화·공포·기절·환혹·넉백 결과가 0이 아니라 감소된 기여로 남는지 검사한다.
- 완전 면역이 필요한 예외가 생기면 데이터에 이유·대체 대응 수단·지속시간을 명시하고 별도 승인한다.
- 각 적은 최소 두 종류의 정상 대응 경로를 가진다. 예: 직접 화력, CC 지연, 심복 재배치, 후보 액티브.
- 적별로 피해 유형·상태·제어·배치 유형에 따른 `time_to_remove`, 돌파율, 유효 제어시간을 집계한다.
- 특정 빌드 등급의 피해 또는 제어 기여가 적 하나 때문에 사실상 0이 되는 경우 밸런스 경고를 낸다.

## 5. v0.16 시각 언어 계약

### 5.1 팩션 의미 이관

현재 내부 진영 ID는 유지하고 활성 시각 토큰만 v0.16에 맞춘다.

| 진영 ID | 목표 주색 | 목표 심볼/마커 | 현재와의 차이 |
|---|---|---|---|
| `partason_faction` | 흑·무채색 + 제한된 금속 보조색 | 검과 방패 | 적/금·왕관에서 변경 |
| `jiane_faction` | 마젠타 + 보조 자주 | 하트 | 색은 근접, 별에서 변경 |
| `kasuha_faction` | 녹색 + 심연 보조색 | 촉수와 눈 | 남청/청록·삼각형에서 변경 |
| `irelai_faction` | 연청색 + 영혼 백색 | 해골과 일렁이는 오라 | 녹/연두·영혼 궤도에서 변경 |
| `judaginda_faction` | 적색 + 흑/회색 | 낫과 피 | 색은 근접, 판결/종에서 변경 |

신규 활성 emblem/marker ID를 사용하되 기존 `partason_crown`, `jiane_star`, `kasuha_abyss`, `irelai_spirit`, `judaginda_bell` 자산과 marker enum은 외부 팩 호환을 위해 바로 삭제하지 않는다. 캠페인 데이터와 UI는 신규 의미 ID를 사용하고 구형 ID는 명시적 레거시 별칭으로만 남긴다.

### 5.2 색상 충돌 방지

팩션색과 상태색은 일부 필연적으로 겹친다. 지아느 마젠타와 환혹 분홍, 카스하 녹색과 독녹, 주다긴다 적색과 출혈 적색을 색만으로 구분하지 않는다.

- 팩션: 프레임, 문양, 외곽 마커
- 상태: 고정 아이콘 실루엣, 작은 움직임, 지속 링/스택 표기
- 위험 경고: 명도 대비와 점멸 패턴

텍스트는 배경 대비 4.5:1, 핵심 아이콘·프레임은 인접색 대비 3:1을 1차 기준으로 검사한다. 색각 시뮬레이션에서도 진영과 상태를 문양만으로 식별할 수 있어야 한다.

### 5.3 자산 방향·스타일

- 아군 `facing=right`, 적 `facing=left`, 정면형은 의도된 예외와 이유를 manifest에 기록한다.
- outline 등급은 `defender_thick`, `enemy_medium`, `ui_icon`으로 구분한다.
- 모든 런타임 캐릭터 자산은 정사각형 캔버스, 투명 모서리, 안전 여백, 작은 크기 silhouette 검사를 통과한다.
- 광택·질감이 많더라도 96px·64px·48px에서 역할이 읽히면 유지한다. 읽히지 않는 표본만 플랫 컬러·형태 단순화 대상으로 삼는다.
- 좌우반전 재사용은 원본/파생 ID와 변경 요소를 manifest에 기록하고 최소 1개, 승인 권장 2개 이상의 차별 요소를 확인한다.

### 5.4 UI 적용 범위

- 후보/심복 선택 카드
- 친위대 및 일반 편대 카드 프레임
- Prelude HUD와 보스 경고
- 도감의 공용/팩션 적 구분
- 결과 타임라인과 적/상태 기여 요약
- 독·출혈·감전·화상·둔화·공포·환혹·기절 아이콘
