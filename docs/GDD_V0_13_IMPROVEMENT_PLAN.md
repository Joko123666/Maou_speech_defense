## 1. 결론

현재 프로젝트는 v0.13을 처음부터 새로 만드는 단계가 아니다. 다음 기반은 이미 실행·검증되어 재사용 가치가 높다.

- 후보 5종, 2:30/5:00/7:30 후보 성장, 후보별 4·4·4·6·4칸 시작 친위대
- 4×6 셀 보드, 2~4칸 편대, 상하 반전, 배치 실패 롤백과 40% 포기 환급
- 일반 수비병력 9종과 27개 Lv.4/Lv.7 특화
- 심복 5종 선택·표현, 일반 Lv.1~7 Cursor 성장, 주그디에드 합동 공격·재구성, 돌격부대 인원·처형·충원
- 공통 화상·출혈·감전, 둔화·공포·환혹·기절의 기존 전투 경로
- 공식 난입 4회, 동적 보스 계획, 후보 지지도·선거 자금·당선·칙령·통치 지지율
- 27개 계약 실행, 게임플레이 스모크, UI 55화면, 후보 5종×3시드 장기 감사 기반

v0.13의 실제 개선 중심은 아래 네 축이다.

1. 첫 계정 일반 병력 해금과 약 49종 검수형 병력세트 풀
2. 독을 포함한 공통 상태이상 계약의 v0.13 의미로 재정의
3. 기존 Cursor 대리 구현을 심복 5종 전용 성장·특화·행동으로 승격
4. 고정 간격 스폰을 기본/보너스 예산과 Alive Pressure가 있는 SpawnDirector로 교체

권장 구현 순서는 다음과 같다.

```text
v0.13 회귀 기준선 고정
→ 첫 계정 해금·초기 12편대
→ 전체 병력세트 카탈로그·A/B/C 제안기
→ 공통 상태이상 v0.13 계약
→ 심복 5종 성장·특화
→ SpawnDirector MVP
→ 공격대 Composition
→ 밸런스·경제·결과 설명·표현 승인
```

이 순서는 확정도가 높은 v0.13 병력 해금부터 전달하고, 상태이상에 의존하는 심복 특화를 상태 기반 이후에 구현하며, 전투 처리량을 바꾸는 SpawnDirector를 콘텐츠 규칙이 안정된 뒤 계측하기 위한 것이다.

### 2.1 남은 기준선 불일치

- 시작 병력·릴리스 잠금·초기 12편대 불일치는 M0~M1에서 해소했다. KI-Ⅱ는 `run.starter_tower_types` 업적으로 발견한 뒤 상점에서 구매하며 기존 v9 보유자는 v10 이관에서 해금을 유지한다.
- 편대 카탈로그와 제안기 불일치는 M2에서 해소했다. `UpgradeOfferService`는 `FormationOfferBuilder`를 통해 A/B/C 슬롯을 만들고, 영구 발견 상태와 런 내 최근 이력을 각각 세이브·오퍼 스냅샷으로 관리한다.
- 공통 상태 불일치는 M3에서 해소했다. `CommonStatusCatalog`는 네 피해 상태와 `legacy_v010` 비교 프로필을, `StatusSourceRegistry`는 영구 소스·자동 타격 적용·안정 출혈 Source ID를 소유하며 고블린 병법은 독/출혈 중 하나를 적용한다.
- 일반 스폰 불일치는 M5에서 해소했다. `EnemyData`의 Spawn Cost·역할 태그, 6개 `SpawnPhaseData`, `EnemySpawnDirector`의 기본/보너스 예산과 실제 활성 일반 적 Alive Pressure를 기존 6구간 가중치에 연결했다.
- 심복 성장·행동 불일치는 M4에서 해소했다. `RetainerProfileData`가 성장 리소스와 행동 프로필을 참조하고, 칸다·기븐·저므조므의 공격 계획은 `RetainerCombatController`, 주그디에드·돌격부대의 특수 계약은 전용 컴포넌트가 소비한다.

## 3. 구현 원칙과 결정 게이트

### 3.1 안정 ID는 유지한다

다음 ID는 표시 의미가 바뀌어도 삭제하거나 일괄 변경하지 않는다.

- `standard_20m`
- Core ID `emerald/sapphire/amethyst/jade/obsidian`
- Cursor ID `iron/silver/gold/platinum/vanguard`
- 일반 병력 ID `rapid/area/pierce/slow/knockback/execute/mark/chain/rubber_golem`
- 기존 편대·특화·업적·상품·저장 ID
- `StageData.final_boss_id`, 체크포인트 `run_id`

새 의미 계층은 Candidate/Retainer/Formation/Status/Spawn 데이터에 추가하고 기존 ID는 어댑터로 연결한다.

### 3.2 `[확정]`과 `[검증]`을 같은 방식으로 구현하지 않는다

- 확정: 초기 병종 4종, 병종 기반 편대 적격, A/B/C 제안 구조, 발견 보정의 존재, 최근 반복 억제의 존재, 크기별 최소 3종.
- 데이터 조정 가능: 편대 이름·최종 좌표·기본 가중치·발견 배율·최근 기억 길이.
- 미확정: 첫 레벨업 병력세트 보장, 4국면/6구간, 상태 카드 레벨 구조, 정확한 상태·Spawn Cost 수치.
- 보류: 모듈 대체 시스템, 모바일 실기·배포.

미확정 항목은 코드 분기나 데이터 프로필로 실험 가능하게 만들고 한 안을 영구 계약으로 고정하지 않는다.

### 3.3 첫 레벨업 보장은 현행을 보존하되 실험 플래그로 둔다

현재 `UpgradeOfferService`는 첫 일반 편대를 보장한다. GDD v0.13은 이를 `[미확정]`으로 표시한다.

권장 조치:

- `first_formation_offer_policy = GUARANTEED | WEIGHTED`를 데이터화한다.
- 초기 기본값은 회귀 위험이 낮은 `GUARANTEED`를 유지한다.
- 두 정책 모두 계약 테스트와 장기 감사 시나리오를 가진다.
- 신규 계정 5런 검증 뒤 최종값을 확정한다.

### 3.4 SpawnDirector MVP는 기존 6구간 위에 먼저 얹는다

4개의 2분30초 국면은 `[제안]`이다. 첫 MVP에서 6구간 데이터까지 동시에 바꾸면 예산 효과와 국면 효과를 구분할 수 없다.

권장 순서:

1. 기존 6구간 적 해금·가중치를 `PhaseResolver` 입력으로 유지한다.
2. Spawn Cost, 기본/보너스 Budget, Alive Pressure만 추가한다.
3. 성장·생존·성능이 수렴한 뒤 4국면 프로필을 A/B 비교한다.

### 3.5 테스트 우회와 실제 신규 계정 잠금을 분리한다

릴리스 데이터에서는 콘텐츠 잠금을 켜고, 스모크·UI·감사 러너는 명시적 테스트 로스터나 테스트 프로필을 주입한다. `Engine.is_editor_hint()`만으로 전체 잠금을 우회하면 신규 계정 계약을 자동 검증할 수 없다.

## 4. 단계별 실행 계획

## M0 — v0.13 회귀 기준선과 데이터 계약

목적: v0.10 완료 기능을 보호하면서 v0.13 증분을 별도 계약으로 측정한다.

작업:

- `ImplementationFreezeContractTest`의 기준 문서를 v0.10 완료본과 v0.13 목표본으로 분리한다.
- `V013MigrationContractTest`를 추가해 시작 병종, 편대 최소 풀, 상태 ID, 심복 성장 데이터, Spawn Cost의 진행 상황을 검사한다.
- 현재 v0.10 스모크 18개 묶음은 삭제하지 않고 회귀 게이트로 유지한다.
- 구현 진행률은 `기반 유지`, `v0.13 증분`, `밸런스/표현`, `모바일/배포` 네 분모로 분리한다.
- 외부 콘텐츠 팩에는 새 필드를 선택적으로 허용하고, 누락 시 구형 동작으로 폴백하는 마이그레이션 버전을 둔다.

완료 조건:

- v0.13 테스트가 미구현 항목을 정확한 실패 사유로 보여준다.
- 기존 v0.10 계약·스모크가 변경 없이 통과한다.

## M1 — 첫 계정 해금과 초기 12개 병력세트

목적: v0.13에서 가장 확정도가 높은 신규 플레이어 수직 절편을 완성한다.

작업:

- 시작 병력을 `rapid`, `pierce`, `area`, `rubber_golem`으로 고정한다.
- KI-Ⅱ `knockback`은 후속 메타 해금으로 이동한다.
- 릴리스 프로필의 콘텐츠 잠금을 활성화하고 테스트 우회는 명시적 주입으로 분리한다.
- v0.13 초기 카탈로그를 2칸 4종, 3칸 4종, 4칸 4종으로 등록한다.
- 기존 `balanced`, `barrage`, `alternating` 등 의미가 같은 안정 ID는 가능한 범위에서 재사용한다.
- 나머지는 충돌 없는 안정 ID와 검수된 셀 좌표를 부여한다.
- 초기 계정에서 각 크기별 적격 편대가 최소 3개인지 자동 검증한다.
- 상점·업적·도감에 고무골렘 초기 상태와 KI-Ⅱ 후속 해금을 반영한다.
- 세이브 마이그레이션은 기존 사용자의 구매·해금을 박탈하지 않는다.

완료 조건:

- 새 세이브에서 정확히 4병종만 일반 병력으로 사용 가능하다.
- 초기 4병종 밖의 병력이 포함된 편대는 제안되지 않는다.
- 2/3/4칸마다 최소 3개, 목표 4개 초기 편대가 실제 보드에 배치 가능하다.
- 기존 세이브는 기존 해금과 구매를 유지한다.
- 신규 세이브·기존 세이브·테스트 전체 해금 세 가지 픽스처가 모두 통과한다.

## M2 — 전체 편대 카탈로그와 FormationOfferBuilder

목적: 해금이 늘수록 원하는 편대가 희석되는 문제를 해결한다.

상태: 완료. 검수형 일반 편대 49종과 전용 제안기·세이브·메트릭·결정적 계약을 구현했다.

데이터 작업:

- 심연의 기둥 +6, 트롤 +6, 서큐버스 +8, KI-Ⅱ +8, 전도탑 +9의 목표 초안을 검수형 데이터로 등록한다.
- 최종 목표는 일반 편대 약 49종이며 크기별 분포가 GDD 범위 안에 들도록 좌표를 조정한다.
- `TowerFormationData`에 의미가 겹치는 `base_weight`를 v0.13 제안 가중치로 명확히 정의한다.
- `role_tags`를 GDD 표준 태그로 정규화한다.
- 발견 보정 대상은 `cells[].tower_id`에서 자동 파생하고 중복 필드를 최소화한다.

런타임 작업:

- `FormationOfferBuilder`를 `UpgradeOfferService` 아래 독립 서비스로 둔다.
- 적격 순서는 활성 → 병종 해금 → 크기 → 실제 배치 위치 → 런 제한으로 고정한다.
- 슬롯 A는 설치 수와 병종 레벨/특화를 반영한 빌드 연계 점수를 사용한다.
- 슬롯 B는 이번 런 미사용 병종과 결손 역할을 우선한다.
- 슬롯 C는 전체 적격 풀의 기본 가중 랜덤을 사용한다.
- 세 슬롯에서 같은 편대를 중복 제시하지 않는다.
- 가능한 경우 주 역할 태그가 모두 같은 세 후보를 피한다.
- 신규 병종 포함 편대는 최초 설치 전까지 데이터형 발견 가중치를 받는다.
- 직전 제시 편대는 런 내 최근 이력으로 감쇠하며, 후보가 부족하면 규칙을 완화한다.
- 하위 목록은 1회 생성·스냅샷하고 재진입/리롤로 바뀌지 않는다.
- 리롤·체크포인트·결정적 감사에서 RNG 소비 순서를 고정한다.

저장·메트릭:

- 영구 `discovered_tower_use_ids` 또는 동등한 필드로 최초 설치 완료를 기록한다.
- 최근 제시 이력은 런 상태이며 영구 세이브에 넣지 않는다.
- 슬롯 유형, 발견 보정 적용, 반복 감쇠, 역할 중복, 적격 풀 크기를 메트릭으로 남긴다.

완료 조건:

- 모든 해금 단계에서 2/3/4칸 적격 풀이 각각 3개 이상이다.
- 미해금 병종이 하나라도 포함된 편대는 제외된다.
- 병종 해금만으로 편대가 자동 적격화되며 별도 편대 구매 플래그가 없다.
- A/B/C 후보가 가능한 경우 서로 다른 목적을 보이고, 후보 부족 시 1~2개만 안전하게 표시한다.
- 발견 보정은 최초 설치 후 해제되고 최근 반복 감쇠는 다음 제안에 반영된다.

## M3 — 공통 상태이상 v0.13 계약 `[완료]`

목적: 심복·일반 병력·친위대가 공유할 수 있는 네 피해 상태와 네 제어 계약을 확립한다.

구조:

```text
CommonStatusCatalog
→ StatusSourceRegistry
→ TowerStatusApplicationService / 후보·친위대 직접 소스
→ Enemy status runtime / ControlResistanceProfileData
→ 카드 적격·UI·메트릭
```

피해 상태:

- `poison`: 공용 스택, 긴 지속, 재적용 시 지속 갱신, 기본 최대 3.
- `bleed`: 인스턴스 ID가 아닌 효과/유닛 종류 `source_id`별 스택과 피해.
- `shock`: 적용 순간 방전, 이벤트별 `visited_targets`, 전이 피해의 새 스택·새 이벤트 금지.
- `burn`: 짧은 지속, 앞쪽 고피해와 시간 감쇠, 재점화 시 지속·감쇠 진행 재설정 여부를 데이터 플래그로 실험.

제어 상태:

- 둔화는 여러 원본을 보존하되 실제 속도에는 가장 강한 값 하나만 적용한다.
- 공포와 기절은 활성 중 재적용을 거부하고 종료 후 짧은 계열 저항시간을 적용한다.
- 환혹은 일반 적 이동 방향을 반전하되 공격·고유 행동은 유지한다.
- 보스 변환·효과량·지속·후속 저항은 기존 `ControlResistanceProfileData`를 확장한다.

호환:

- 안정 메트릭 ID `burn/bleed/shock`는 유지하고 `poison`만 추가한다.
- 기존 화상·출혈 수치를 즉시 삭제하지 않고 `legacy_v010` 프로필로 재현 가능하게 둔다.
- 고블린 병법의 “독을 만들지 않음” 스모크를 독/출혈 선택과 상태 카드 적격 계약으로 교체했다.
- 공통 상태 성장의 정확한 레벨 구조는 데이터화하고 기존 Lv.1~7을 비교 프로필로 보존한다.

완료 조건:

- 독 공용 최대 스택, 출혈 안정 Source ID, 감전 루프 차단, 화상 재점화 정책을 단위 계약으로 검증한다.
- 상태 전이와 소환이 재귀적으로 무한 생성되지 않는다.
- 영구 적용 소스를 얻기 전에는 해당 상태 성장 카드가 나오지 않는다.
- 1×/2×/3×에서 같은 시드의 논리 결과가 일치한다.
- 다중 상태 아이콘과 전투 효과가 기존 성능 예산을 넘지 않는다.

## M4 — 심복 5종 전용 성장·특화 `[완료]`

목적: 표시명만 심복인 기존 Cursor 성장축을 v0.13의 실제 캐릭터 성장축으로 전환한다.

- `RetainerProfileData`가 성장 데이터와 필요한 행동 프로필을 참조한다.

5. 돌격부대: 기존 인원·처형·충원을 다다익선/구독 제물/액티브 소환진으로 이관.

구조 원칙:

- 칸다·기븐·저므조므의 고유 행동은 `GameController` 분기문이 아니라 독립 컴포넌트/컨트롤러로 구현한다.
- `CandidateMechanicsFactory`는 Retainer 프로필로 필요한 컴포넌트를 계획·생성한다.
- 후보와 심복의 선호 관계는 전투 보너스를 주지 않는다.
- 액티브 연동은 후보 종류와 무관하게 선택한 심복의 계약으로 작동한다.

UI·결과:

- 출격 카드에 실제 기본 공격·고유 규칙을 표시한다.
- 성장 카드와 HUD에서 `심복 Lv`, Lv.4 특화, Lv.7 완성을 별도 축으로 표시한다.
- 결과에 심복 피해·처형·제어·회수·고유 자원 기여를 역할에 맞게 요약한다.

완료 조건:

- 후보 5종×심복 5종의 25조합에서 선택·성장·액티브 연동이 유효하다.
- Lv.4 특화는 한 번만 선택되고 Lv.7 완성은 선택 특화와 일치한다.
- 기븐 한 공격 시퀀스당 환혹 판정 1회, 저므조므 공포 저항, 주그디에드 영속계약 감산, 돌격부대 소환진 snapshot을 계약으로 검증한다.
- 기존 주그디에드·돌격부대 회귀 계약이 신규 심복 계약으로 대체된 뒤에도 기능을 잃지 않는다.

## M5 — SpawnDirector MVP `[완료]`

목적: 강한 빌드가 같은 10분 안에서 실제 추가 적과 XP를 처리하되 약한 빌드의 기본 난이도를 숨겨서 낮추지 않게 한다.

데이터:

- `EnemyData.spawn_cost > 0`, `role_tags`, 필요 시 패킷 제한 태그를 추가한다.
- `SpawnPhaseData`에 기본 예산률, 보너스 예산률, 목표/최대 압박도, 최대 패킷 비용을 둔다.
- 첫 MVP는 기존 6구간 적 해금·가중치를 사용한다.

구조:

```text
EnemySpawnDirector
├─ PhaseResolver
├─ SpawnBudgetController (base / bonus)
├─ AlivePressureTracker
└─ EnemySpawner
```

런타임:

- 기본 예산은 시간에 따라 반드시 공급해 스테이지 기준 난이도를 보장한다.
- 보너스 예산은 Alive Pressure가 목표보다 낮을 때만 공급하고 최대 압박도에서 중지한다.
- 보스는 일반 예산을 소비하지 않는다.
- 보스 활성 중 보너스 배율은 데이터로 낮추되 기본 스폰은 유지한다.
- PREPARATION/LEVEL_UP/FORMATION 상태에서 게임 시간이 멈추면 예산과 압박 시간도 같은 규칙으로 멈춘다.
- 도전 단계의 스폰 간격 감소는 예산률·최대 패킷·목표 압박도 보정으로 이관한다.
- 분열 자식·보스 소환은 중복 예산 소비 없이 Alive Pressure에 일관되게 포함한다.

메트릭:

- 기본/보너스 예산 누적·소비, 평균/최대 Alive Pressure, 기본/보너스 출현 수와 XP, 객체 피크를 분리한다.
- 평균 런 대비 상위 처리량 런의 추가 XP가 목표 20~25%를 넘는지 경고한다.

완료 조건:

- 모든 일반 적의 Spawn Cost가 양수다.
- `target_alive_pressure <= max_alive_pressure`와 Phase 시간 무공백·무중첩을 검증한다.
- 강한 결정적 프로브가 기본 프로브보다 추가 적과 XP를 얻되 보너스 상한을 넘지 않는다.
- 약한 프로브에서도 기본 예산 공급은 사라지지 않는다.
- 보스와 일반 예산, 기본과 보너스 예산이 서로 섞이지 않는다.
- 1×/2×/3×에서 출현 결정과 결과가 일치하고 기존 데스크톱 성능 게이트를 통과한다.

## M7 — 밸런스·경제·결과 설명·표현 `[진행 중]`

완료된 수직 절편: `RunOutcomeSummary`가 후보/친위대/심복 성장, 일반·친위대 편대 수와 친위대 기여, 상태 적용·피해, 기본/보너스 Spawn·패킷 횟수를 안정 데이터로 묶습니다. 일반 결과·체크포인트·밸런스 감사가 같은 요약을 보존하며 결과 화면은 최종 보드·최고 피해·지지도·자금과 중복되던 전체 빌드 문자열 대신 짧은 성장 및 전투 기여 줄을 표시합니다. 1280×720 승리·패배 스냅샷에서 잘림과 고립 줄바꿈이 없음을 확인했습니다.

완료된 경제 절편: `FirstFiveRunEconomyAudit`가 실제 5개 상품·11개 업적·표준 보상 리소스를 사용하되 세이브를 변경하지 않는 순수 시뮬레이션을 제공합니다. 3/5/7/8.5/10분 대표 신규 계정 경로와 매 런 최저가 우선 구매 정책에서 첫 패배 +45, 첫 발견 1런, 첫 구매 3런, 5런 후 7/9 병종, 이후 표준 클리어 반복 시 7런 완전 해금을 기록했습니다. 독립 `economy_audit.tscn`과 계약 테스트가 첫 구매 3런 이내·5런 전체 상품 발견·8런 이내 완전 해금을 회귀 게이트로 고정합니다.

완료된 장기 감사 절편: 개인 세이브의 발견 이력이 제안 풀을 바꾸지 않도록 신규 계정 시작 병종 4종을 `starter_discovery_v1` 픽스처로 고정한 보고서 스키마 v9를 사용했습니다. 5후보×3시드×600초 15/15 유효 런은 평균 531.0초·완주율 86.6%로 전체 기준을 통과했습니다. Lv.24까지를 보존하고 Lv.25부터 요구 경험치 증가 배율을 1.7로 조정해 570초 이상 5개 표본 평균을 Lv.31.4에서 Lv.30.0으로 낮췄습니다. 지아네 `몽마의 권위`의 일반/보스 핵 돌파 피해 ×0.5는 동일 3시드 A/B에서 평균 +34.1초·+5.6%p 효과를 보였습니다. A/B/C는 각 92회 제시되고 45/17/30회 선택됐으며 모든 라운드가 복수 역할을 제공했습니다. 상세 근거는 `docs/RUNTIME_BALANCE_AUDIT_2026-08-24.md`에 있습니다.

밸런스:

- 후보×심복 조합 승률, 심복 평균 투자 레벨, 특화 선택률을 추가한다.

- 상태 소스 확보 시점, 상태 피해/제어 기여, Spawn 기본/보너스 XP 비율을 측정한다.

경제:

- 완료: 신규 세이브 첫 5런의 패배 보상, 첫 병종 발견, 첫 구매와 9병종 완전 해금 예상 속도를 실제 카탈로그·보상식 기반으로 검증한다.
- 완료: A/B/C 각 89회 제시, 선택 55/17/17회, 라운드별 복수 역할 100%, 평균 적격 풀 14.7종으로 역할 접근성을 확인했다.

결과 화면:

- 후보/심복/친위대/일반 편대/상태/Spawn 처리량을 짧은 역할별 요약으로 보여준다.
- 최종 보드, 최고 피해 병력, 후보 지지도, 선거 자금과 중복되지 않게 정보 위계를 조정한다.

표현:

- 완료: 지아네 `몽마의 권위` 돌파 완화에는 사파이어·마젠타 꿈 장벽을, 주다긴다 처형 성공에는 흑요석·적색 판결 인장을 실제 판정 위치에 표시한다. 두 효과는 전투 수치와 분리하고 공통 효과 예산을 사용한다.

- 최종 SD 시트·음성 범위는 별도 승인 대상으로 유지한다.
- 모바일 실기·배포는 재개 지시 전까지 완료로 표시하지 않는다.

완료 조건:

- 후보·심복·병종·편대 크기 중 단일 선택이 비정상적으로 독점하지 않는다.

- 1280×720의 신규 성장·편대·결과 UI에 잘림·겹침이 없다.
- 모바일 미검증 상태를 별도 출시 준비도에 계속 명시한다.

## 7. 통합 완료 판정

v0.13 핵심 구조 완료는 아래를 모두 만족할 때만 선언한다.

- 신규 계정 초기 병종이 정확히 고블린/오크/해골/고무골렘이다.
- 병종 해금만으로 검수형 편대가 자동 적격화되고 각 해금 단계에서 크기별 최소 3종이 존재한다.
- A/B/C 편대 제안, 발견 보정, 최근 반복 억제, 역할 다양성이 실제 런과 결정적 테스트에서 작동한다.
- 독/출혈/감전/화상과 둔화/공포/환혹/기절의 v0.13 계약이 작동한다.
- 심복 5종이 자유 조합, Lv.1~7, Lv.4 3택, Lv.7 완성과 고유 행동을 가진다.
- SpawnDirector 기본/보너스 예산과 Alive Pressure로 강한 런의 추가 전투·XP가 생긴다.
- 기존 후보·친위대·9병종·4×6 보드·공식 난입·메타 저장이 회귀하지 않는다.
- 결과 화면이 후보/심복/편대/상태/보드 기여를 설명한다.
- 최신 파싱·스모크·UI·다중 시드 성능/밸런스 감사 기록이 있다.

다음 항목은 핵심 구조 완료와 분리한다.

- 4국면 vs 6구간 최종 선택
- 정확한 상태·Spawn Cost·경제 수치 수렴
- 공격대 확장 콘텐츠와 적 승격
- 모듈 대체 시스템
- 최종 SD 프레임·음성 승인
- 모바일 실기·Android 배포 승인
