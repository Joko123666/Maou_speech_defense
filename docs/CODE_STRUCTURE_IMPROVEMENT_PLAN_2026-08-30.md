# 코드 구조 개선 실행 계획 — 2026-08-30

## 1. 목적

현재 전투 기능은 동작하지만 `GameController`가 4,114행·399개 함수로 여전히 큽니다. 이미 공격·상태·보상·종료 흐름의 다수 경계가 서비스로 분리됐으므로, 앞으로는 행 수를 줄이는 것 자체보다 다음 세 가지를 우선합니다.

1. 게임 규칙과 실행 순서를 한 소유자에게 모읍니다.
2. 실패한 실행이 자원·메트릭·HUD 일부만 변경하지 않도록 원자성을 보장합니다.
3. 장면 컨트롤러는 Node 연결, 메트릭, HUD, 연출 조정에 집중시킵니다.

이 계획은 전투 수치와 사용자 경험을 임의로 바꾸는 대규모 재작성 계획이 아닙니다. 한 번에 하나의 수직 경계를 추출하고 매 단계 전체 회귀를 통과시키는 증분 계획입니다.

## 3. 실행 원칙

### 책임 경계

- 서비스는 자격 판정, 값 정규화, 실행 순서, 성공/실패 결과를 소유합니다.
- `GameController`는 장면 노드 조회, 서비스 콜백 연결, 메트릭, HUD, 연출만 소유합니다.
- 장면 의존성이 필요한 경우 `Callable`로 주입하고, 서비스가 SceneTree를 탐색하지 않습니다.
- 결과는 안정적인 필드와 실패 사유를 가진 `Dictionary`로 반환합니다.
- 콜백 누락이나 실행 거부는 부작용 전에 종료합니다.
- 동일 프레임의 동기 재진입이 있는 죽음 처리에서는 상태 전환 순서를 계약 테스트로 고정합니다.

### 변경 단위

- 한 단계에서 하나의 게임플레이 경계만 추출합니다.
- 수치 변경과 구조 변경을 같은 단계에 섞지 않습니다.
- 불가피한 동작 수정은 기존 결함, 새 계약, 사용자 영향 범위를 함께 기록합니다.
- 모든 단계는 독립적으로 배포 가능한 녹색 상태에서 끝냅니다.

### 우선순위 판정

다음 조건을 많이 만족할수록 먼저 추출합니다.

1. 자원 소비와 실행 성공 여부가 분리되어 있습니다.
2. 세 개 이상의 보조 함수가 하나의 규칙을 나누어 소유합니다.
3. 동기 콜백 재진입 또는 임시 상태 플래그가 있습니다.
4. modifier 조회, 공간 질의, 피해 적용, 메트릭이 한 함수군에 섞여 있습니다.
5. 순수 계약 테스트 없이 전체 스모크에만 의존합니다.

행 수와 함수 수는 추세 지표로만 사용하며, 의미 있는 오케스트레이션을 억지로 분리하지 않습니다.

## S1 — `CandidateDeathWaveLaunchService` 추출

상태: **완료 (2026-08-30)**. 우선순위 P0.

`CandidateDeathWaveLaunchService`가 modifier 조회, 3구간 영혼 유효값, 파도 프로필, 단일 실행 요청과 성공 후 영혼 소비를 소유합니다. `LoadoutManager.candidate_soul_effective_value()`는 호환 facade로 서비스를 위임하며, `GameController`는 성공 결과에 대해서만 후속 창·사령 표시·메트릭·HUD를 정산합니다. 실행 거부는 영혼과 모든 표시 상태를 보존합니다.

검증은 300 영혼 성공 발동, 실행 중 영혼 예약과 성공 후 소비 순서, 실행 거부 보존, 영혼 성장 비활성 기본 파도, 협력자 누락 조기 거부를 고정했습니다. 첫 전체 스모크에서 신규 테스트 지역 변수 2개의 타입 추론 오류를 발견해 `int`로 명시한 뒤 Godot 4.7 파싱, 전체 `SMOKE TEST PASS`, `TUTORIAL RUNTIME SMOKE PASS`, verbose 오류·누수 필터 종료 코드 0을 확인했습니다.

### 현재 문제

`GameController._launch_irelai_death_wave()`와 세 보조 함수가 다음 책임을 나누어 갖습니다.

- 영혼 수확 활성 여부 조회와 전체 영혼 소비.
- 0~300 영혼의 100%→50%→25% 유효값 환산.
- 피해, 세로 반경, 처치당 사령, 생성 사령 피해, 후속 창, 영혼 상한 구성.
- `DeathWaveController.launch()` 요청.
- 사령 표시, 메트릭, HUD 정산.

현재는 `launch()` 반환값을 사용하지 않습니다. 소환 예산 부족이나 런타임 준비 실패로 발동이 거부돼도 영혼이 먼저 소모되고 시전 메트릭·HUD가 기록될 수 있습니다.

### 목표 책임

신규 `scripts/combat/candidate_death_wave_launch_service.gd`가 다음을 소유합니다.

1. 필수 입력과 실행 콜백 유효성 검사.
2. 영혼 수확 활성 여부와 현재 영혼 스냅샷 확인.
3. 유효 영혼값과 파도 프로필 구성.
4. 단 한 번의 파도 실행 요청.
5. 실행 성공 뒤에만 영혼 소비 확정.
6. `launched`, `reason`, `consumed_souls`, `effective_souls`, `damage`, `half_height`, `duration`, `spirit_gain`, `generated_spirit_damage_multiplier`, `post_wave_window`, `soul_cap` 반환.

`GameController`는 다음만 수행합니다.

- 목표지점 Y 좌표와 후보 색을 전달합니다.
- 성공 결과의 `post_wave_window`를 보관합니다.
- 사령 표시를 0/상한으로 갱신합니다.
- `irelai_death_wave_cast`, `irelai_souls_spent` 메트릭과 HUD 알림을 정산합니다.

### 고정 실행 계약

- 영혼 수확 비활성: 보유 영혼을 소비하지 않고 기본 프로필로 발동합니다.
- 300 영혼과 현재 데이터 `0.006`, `1.2` 기준: 유효값 175, 기본 피해 100이면 요청 피해 205, 세로 반경 355, 처치당 사령 2입니다.
- 파도 지속시간은 기존 2.4초를 유지합니다.
- `active_generated_spirit_damage`와 `post_active_spirit_window`는 기존 modifier를 그대로 사용합니다.
- 실행 성공 시에만 영혼, 후속 창, 메트릭, HUD를 정산합니다.
- 실행 거부 또는 콜백 누락 시 영혼과 표시 상태를 보존합니다.
- 기존 진행 중 파도 교체·공통 소환 예산 정책은 `DeathWaveController`가 계속 소유합니다.

## S2 — 죽음의 파도 적중·완료 상태 경계 통합

상태: **완료 (2026-08-30)**. 우선순위 P1.

`CandidateDeathWaveRuntimeService`가 적중 재진입 플래그, 적 사망 중 동기 생성된 저주 사령 표시, 남은 파도 처치 사령 계산, 후속 창의 1회 소비와 런 종료 초기화를 소유합니다. `GameController`의 세 임시 상태는 제거했고 피해·사령 추가·메트릭·활성 창 콜백만 연결합니다. 피해 메트릭은 기존 사건 순서를 보존하도록 적중 재진입 상태 해제 뒤, 파도 사령 추가 전에 정산합니다. 서비스는 91행·9개 인스턴스 함수이며 컨트롤러는 4,096행·395개 인스턴스 함수입니다.

### 현재 문제

`resolving_death_wave_hit`, `death_wave_curse_spirit_generated`, `pending_irelai_post_wave_window` 세 상태와 적중·완료 콜백이 `GameController`에 남아 있습니다. 적중 중 적 사망 콜백이 동기로 재진입해 친위대 저주 사령을 만들 수 있으므로, 단순 함수 이동만으로는 안전하지 않습니다.

### 목표 책임

상태형 `CandidateDeathWaveRuntimeService`가 다음을 소유합니다.

- S1 성공 결과의 후속 창 무장.
- 적중 시작/종료와 저주 사령 선생성 표시.
- 실제 피해 적용 뒤 남은 처치 사령 수 계산.
- 파도 완료 시 후속 사령 활성 창 요청과 내부 상태 초기화.
- 런 종료 시 모든 임시 상태 초기화.

`GameController`는 피해·사령 추가 콜백, 메트릭, 파도 신호 연결만 담당합니다.

### 계약 테스트

- 일반 처치: 요청 사령 수 전체를 추가합니다.
- 저주 사령 동시 생성: 중복 1기를 차감합니다.
- 비치명 적중: 사령을 생성하지 않습니다.
- 무효·비활성 적: 피해와 상태를 변경하지 않습니다.
- 완료: 후속 창을 한 번만 시작하고 0으로 초기화합니다.
- 종료/취소: 무장된 후속 창과 재진입 플래그가 남지 않습니다.

### 완료 기준

- 세 임시 상태가 `GameController`에서 제거되거나 읽기 전용 위임으로 축소됩니다.
- 동기 사망 재진입 순서가 계약으로 고정됩니다.
- 전체 회귀에서 죽음의 파도 사령 수와 기존 메트릭이 보존됩니다.

일반 처치의 전체 사령 요청, 동기 저주 사령 생성 시 1기 차감, 비치명 적중, 종료된 게임의 무부작용 거부, 8초 후속 창의 정확히 1회 소비, 누락 콜백과 런 종료 초기화를 구조 계약으로 고정했습니다. Godot 4.7 파싱, 일반 전체 스모크, 튜토리얼 런타임, verbose 오류·누수 검사가 모두 종료 코드 0으로 통과했습니다.

## S3 — 사령 생성·만료 후속 효과 추출

상태: **완료 (2026-08-30)**. 우선순위 P1.

`CandidateNecromancyEffectService`가 생성 공포와 만료 폭발의 성장 자격, 수치 정규화, 단일 공간 질의, 공간 순서의 공포·피해 적용과 성공 요약을 소유합니다. `GameController`는 생성·만료 기본 메트릭을 신호 수신 즉시 기록하고, 성공 결과의 추가 메트릭과 연출만 정산합니다. 서비스는 82행·4개 인스턴스 함수이며 컨트롤러는 4,092행·395개 인스턴스 함수입니다.

### 대상

- `_on_irelai_spirits_generated()`의 생성 공포.

### 목표 책임
