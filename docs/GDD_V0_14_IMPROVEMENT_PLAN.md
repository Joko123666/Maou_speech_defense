## 0. 결론

v0.14의 신규 핵심은 후보·심복·상태·스폰을 다시 만드는 것이 아니라 **49개 일반 편대의 병종 수와 블록 형태를 의도적으로 재분배하는 것**이다. 기존 v0.13 기능과 안정 ID는 유지하고 다음 순서로 개선한다.

```text
분포 규칙의 산술 충돌 해소
→ FormationData 메타데이터·검증 계약
→ 49개 카탈로그 재검수
→ 카드·도감·메트릭 노출
→ 5후보×3시드 장기 재감사
→ 잔여 밸런스·표현 승인
→ 모바일·배포 게이트(재개 지시 후)
```

비모바일 v0.14 완료의 최우선 범위는 M0~M5다. M6 표현 승인은 출시 품질 범위이며, M7 모바일·배포는 현재 차단된 별도 출시 게이트다.

## 1. M0 시작 당시 구현 기준선과 실제 차이

### 이미 유지할 기반

- 후보 5명, 심복 5명, 후보별 4·4·4·6·4칸 시작 친위대
- 4×6 보드, 일반 2·3·4칸 편대, 상하 반전, 배치 롤백과 40% 포기 환급
- 일반 병력 9종과 27특화, 일반 편대 49종과 크기별 15/17/17 분포
- 신규 계정 G/O/S/R 4병종과 초기 2·3·4칸 각 4개 편대
- A 빌드 연계/B 확장/C 자유 제안, 역할 다양성, 발견 보정, 최근 반복 감쇠
- 독·출혈·감전·화상, 공포·환혹·기절·둔화와 보스 제어 저항
- 6개 Spawn Phase, 기본/보너스 예산, Alive Pressure, 3개 공격대 패킷
- 후보 5종×3시드×600초 재현 가능 감사와 Forward Mobile UI 59개 기준선

### 작업 시작 시 확인한 v0.14 미구현 영역

M0 시작 당시 `TowerFormationData`에는 `role_tags`, `formation_score`, `can_vertical_flip`은 있지만 GDD가 권장한 `shape_class`와 `placement_difficulty`가 없었다. 따라서 카탈로그의 형태 분포를 런타임·UI·계약 테스트가 직접 판정하지 못했다. 이 차이는 M1~M2에서 해소됐다.

2026-08-24 작업 전 `DataRegistry`의 일반 편대 49종을 좌표와 병종 ID로 정적 집계한 결과는 다음과 같다.

| 항목 | 현재 | v0.14 목표 | 판정 |
|---|---:|---:|---|
| 1종 편대 | 2개, 4.1% | 20~25% | 부족 |
| 2종 편대 | 18개, 36.7% | 50~55% | 부족 |
| 3종 편대 | 20개, 40.8% | 20~25% | 과다 |
| 4종 편대 | 9개, 18.4% | 0개 | 금지 규칙 위반 |
| LONG | 15개, 30.6% | 약 30% | 총량만 우연히 일치, 전부 2칸 |
| BEND | 18개, 36.7% | 약 25% | 3칸에 편중 |
| COMPACT | 16개, 32.7% | 약 20% | 4칸 2×2에 편중 |
| STEP | 0개 | 약 25% | 부재 |

형태 수치는 메타데이터가 없으므로 현재 좌표를 기준으로 추론한 값이다. 3칸 17종은 모두 ㄱ자이며, 4칸은 16종이 2×2, 1종만 굴곡형이다. v0.14는 단순 필드 추가가 아니라 병종 배열과 좌표를 함께 다시 검수해야 한다.

## 2. 먼저 확정할 실행 규칙

### 2.1 형태 비율의 산술 충돌

현재 15/17/17 크기 분포에서 2칸 편대 15개는 연결성 때문에 모두 LONG이다. 여기에 GDD의 크기별 목표인 3칸 LONG 40%와 4칸 LONG 25~30%를 적용하면 전체 LONG은 약 55%가 되어 “전체 약 30%”와 동시에 일치할 수 없다. 또한 직교 연결 3칸 폴리오미노는 직선과 ㄱ자 두 종류뿐이므로 3칸의 “기타 비대칭 20%”를 독립 형태로 만들 수 없다.

계획에서는 다음 해석을 채택한다.

- 전체 LONG 약 30%는 상한이 아니라 **장축형 최소 확보 의도**로 해석한다.
- 일반 편대의 직교 연결 계약과 15/17/17 크기 분포를 유지한다.
- 3칸은 LONG/BEND만 사용하고 방향·내부 병력 순서로 비대칭성을 확보한다.
- STEP은 실제 S/Z 계열이 가능한 4칸에서만 사용한다.
- GDD 자체를 다음에 개정할 때 전체 형태 표에는 이 실행 분포를 반영한다.

### 2.2 실행 목표 분포

병종 수는 49종에 맞춰 목표 범위 안의 정확한 정수 분포로 고정한다.

| 서로 다른 병종 수 | 목표 개수 | 비중 |
|---:|---:|---:|
| 1종 | 11 | 22.4% |
| 2종 | 26 | 53.1% |
| 3종 | 12 | 24.5% |
| 4종 | 0 | 0% |

형태는 구조적으로 가능한 크기별 분포를 사용한다.

| 크기 | LONG | BEND | COMPACT | STEP | 합계 |
|---:|---:|---:|---:|---:|---:|
| 2칸 | 15 | 0 | 0 | 0 | 15 |
| 3칸 | 7 | 10 | 0 | 0 | 17 |
| 4칸 | 5 | 4 | 4 | 4 | 17 |
| 전체 | 27 | 14 | 4 | 4 | 49 |

초기 12종은 튜토리얼 역할을 분명히 한다.

- 2칸 4종: 가로 2, 세로 2
- 3칸 4종: LONG 2, BEND 2
- 4칸 4종: LONG/BEND/COMPACT/STEP 각 1
- 1/2/3종 편대를 모두 포함하고 4종 완전 혼성은 제거
- 첫 계정 G/O/S/R만 사용하며 모든 크기에서 최소 3개 적격 편대 유지

### 2.3 안정성과 점수 계약

- 49개 일반 편대의 안정 ID와 15/17/17 크기 수는 유지한다.
- 친위대 5종과 숨김 증원 1종은 일반 카탈로그 분포 집계에서 제외한다.
- 형태 난도는 `formation_score`, `raw_power_score`, `output_multiplier`에 합산하지 않는다.
- 90도 회전은 추가하지 않고 상하 반전만 유지한다.
- 병종·좌표 변경으로 이름이나 설명이 거짓이 되는 편대는 표시 문구를 함께 수정한다.
- 저장 스키마는 편대 ID가 유지되는 한 올리지 않는다. 실제 저장 필드 변경이 생길 때만 별도 이관을 추가한다.

## 3. 단계별 개선 계획

### M0 — v0.14 기준선 동결과 결정 계약 `P0 / S`

작업:

- 이 문서의 병종 수 11/26/12/0과 크기별 형태 분포를 실행 기준으로 고정한다.
- 현재 49개 ID·15/17/17, 초기 12개 ID, 친위대/증원 제외 규칙을 회귀 기준선으로 남긴다.
- `GDD §31` 미확정 항목을 이미 채택된 값, 수치 검증 필요, 보류로 분류한다.

완료 조건:

- 카탈로그 변경 전에 실패하는 v0.14 전용 계약 테스트의 기대값이 먼저 정의된다.
- v0.13 안정 ID·세이브·콘셉트 호환 경계가 명시돼 있다.
- 형태 분포의 산술 충돌에 대해 구현자가 임의 해석할 여지가 없다.

### M1 — FormationData 메타데이터와 validator `P0 / M`

작업:

- `TowerFormationData`에 `shape_class`와 `placement_difficulty`를 추가한다.
- `shape_class`는 `LONG/BEND/COMPACT/STEP`, 난도는 `0 쉬움 / 1 보통 / 2 까다로움`으로 제한한다.
- 서로 다른 병종 수 계산 API와 좌표 시그니처 기반 형태 검증을 추가한다.
- LONG은 1×N/N×1, COMPACT는 4칸 2×2, STEP은 4칸 S/Z, BEND는 3칸 ㄱ자와 검수된 4칸 L/T 시그니처만 허용한다.
- 일반 2칸은 1~2종, 3·4칸은 1~3종, 일반 4칸 4병종 금지를 validator에 넣는다.
- 친위대의 비직교·희소 배치는 기존 예외를 유지하고 일반 분포 validator를 적용하지 않는다.

완료 조건:

- 메타데이터 누락·잘못된 값·좌표와 클래스 불일치가 계약 테스트에서 실패한다.
- 형태 메타데이터를 바꿔도 편성점수와 전투 출력이 달라지지 않는다.
- 기존 외부 콘텐츠 팩은 명시적 기본값 또는 검증 오류 중 하나로 예측 가능하게 처리된다.

### M2 — 49개 일반 편대 카탈로그 재검수 `P0 / L`

작업:

- 9개 4병종 편대를 2~3종 혼성으로 재설계한다.
- 과다한 3종 편대를 1종 반복 가치가 높은 고블린·KI-Ⅱ·전도탑·고무골렘 중심의 1종 편대와 역할이 선명한 2종 편대로 분산한다.
- 고가 트롤 스나이퍼와 지원형 서큐버스는 동일 병종 반복을 피하고 저·중점수 보조와 조합한다.
- 3칸 직선 7종, 4칸 직선 5종, 4칸 BEND/COMPACT/STEP 각 4종을 만든다.
- 초기 12종을 M0의 학습 분포로 재배치하고 이후 각 병종 해금 단계의 2/3/4칸 최소 3종을 다시 계산한다.
- 각 변경 편대의 이름·설명·역할 태그·기초 편성점수·정규화 출력을 실제 병종/형태와 대조한다.

완료 조건:

- 일반 49종, 크기 15/17/17, 병종 수 11/26/12/0, 형태 27/14/4/4가 정확히 일치한다.
- 초기 12종과 모든 해금 단계에서 크기별 적격 편대가 최소 3개다.
- 셀 중복·음수 좌표·비정규화·비직교 연결·잘못된 Tower ID가 0건이다.
- 기존 안정 편대 ID의 누락·중복이 0건이다.

### M3 — 카드·도감·제안 메트릭 `P1 / M`

작업:

- 병력 세트 하위 카드와 편대 상세/도감에 형태, 배치 난도, 병종 수를 짧게 표시한다.
- A/B/C 제안 메타데이터와 `RunMetrics`에 `shape_class`, `distinct_tower_count`, 유효 배치 위치 수를 기록한다.
- 형태를 즉시 제안 가중치에 섞지 않는다. 먼저 출현·선택·포기 데이터를 수집하고 편중이 재현될 때만 별도 보정을 추가한다.
- 첫 일반 편대가 설치되기 전 병력 세트 1장을 보장하고, 직접 성장 후보가 부족하면 서로 다른 크기의 선택 병력 세트 1장까지 허용하는 계약으로 고정한다. 필수 첫 카드만 정책 교체에서 보호한다. (2026-09-04 개정)

완료 조건:

- 1280×720에서 A/B/C 카드 3장과 상세 화면의 텍스트·미니 보드가 잘리거나 겹치지 않는다.
- 한 카드에서 형태와 내부 병력 배열이 모순되지 않는다.
- 첫 편대 설치 전에는 필수 병력 세트 1장과 서로 다른 크기의 선택 병력 세트 최대 1장, 설치 후에는 화면당 최대 1장을 유지한다. 하위 최대 3개와 배치 불가 편대 제외도 유지한다.

### M4 — 자동 검증과 장기 플레이 재감사 `P0 / L`

상태: **완료 (2026-08-24)**. 보고서 스키마 v11의 고정 틱 감사에서 1×/2×/3× 논리 결과가 일치했고, 15/15 장기 런의 기술·통합 밸런스 게이트가 통과했다. 전체 평균 완주율 92.11%, 570초 이상 8런 평균 Lv.29.875, 복수 역할 제안 87/87, 타임아웃·무효 보드·성능 실패 0이다. 상세 결과는 `docs/RUNTIME_BALANCE_AUDIT_2026-08-24_V014_M4.md`를 따른다.

작업:

- `V014FormationCatalogContractTest`를 추가하고 스모크 동결 목록에 연결한다.
- 기존 `V013MigrationContractTest`와 `FormationOfferBuilderContractTest`는 v0.13 세이브/제안 호환과 v0.14 분포 책임을 분리한다.
- Forward Mobile UI 스냅샷에서 초기/후기 LONG·BEND·COMPACT·STEP 카드와 실제 배치를 각각 확인한다.
- 동일 신규 계정 픽스처로 후보 5종×3시드×600초 매트릭스를 다시 실행한다.
- 형태/병종 수별 출현·선택·포기, 평균 유효 배치 수, 최종 점유율, 고립 셀, 최종 레벨과 보너스 XP를 집계한다.

필수 게이트:

- Godot 파싱·전체 스모크 종료 코드 0
- 잘못된 블록·배치 오류·감사 타임아웃·성능 실패 0
- 모든 장기 런에서 복수 역할 제안 접근 유지
- 전체 평균 완주율 기존 85% 게이트 유지, 후보별 85% 미만은 독립 경고로 남김
- 570초 이상 표본 평균 최종 레벨이 승인 상한 Lv.30을 넘지 않음
- 1×/2×/3× 논리 결과 동등성 유지
- UI 스냅샷 생성 성공뿐 아니라 실제 이미지 시각 승인

### M5 — 잔여 수치 검증과 밸런스 수렴 `P1 / M~L`

작업:

- 편대 재배치가 후보별 생존과 병력 효율에 미친 효과를 먼저 측정한 뒤 지아느 81.0%·주다긴다 78.4%를 조정한다.
- 주다긴다의 로컬 `area/rapid` 지속 화력 3.17배가 편대 표본인지 실제 수치 편향인지 추가 시드로 판정한다.
- 상태 성장 카드의 실제 도달 레벨·출현 빈도와 친위대 성장 50%/2회 누락 보장의 실제 완료율을 메트릭으로 검증한다.
- 평균 런과 상위 10% 런의 최종 레벨·총 XP 격차를 직접 산출한다.
- 보너스 Spawn XP 3.63%를 보수적 보너스로 승인할지 GDD의 20~25% 방향으로 올릴지 결정한다. 상향 시 한 번에 목표치로 점프하지 않고 작은 A/B 단계로 검증한다.

완료 조건:

- 후보·병력·형태 조정은 한 번에 한 축만 바꾸고 동일 픽스처 대조군을 남긴다.
- 통합 경고 0과 후보별 잔여 경고의 승인/수정 근거가 문서화된다.
- 강한 런의 성장 격차가 체감 가능하지만 초기 행운만으로 최종 레벨이 폭주하지 않는다.

### M6 — 연출·접근성·1×/3× 승인 `P1 / M`

작업:

- 새 LONG/STEP 편대가 실제 전장에서 병력 실루엣과 방향성을 전달하는지 1×와 3×에서 확인한다.
- 상태·소환·감전·다단히트가 겹칠 때 후보 액티브와 공식 난입 경고를 가리지 않도록 효과 우선순위를 승인한다.
- 후보·심복 SD의 최종 애니메이션 범위와 캐릭터 음성을 제작할지 이번 릴리스에서 제외할지 결정한다.
- 화면 흔들림·플래시·사운드 토글과 색상 외 아이콘/문양/움직임 중복 표시를 실제 설정·전투 경로에서 확인한다.

완료 조건:

- 대표 후보 5조합의 1×/3× 전투 화면에서 핵심 경고·병력·상태가 식별된다.
- 음성 미제작도 명시적 릴리스 결정으로 인정하며 미완료 항목처럼 방치하지 않는다.
- 접근성 토글이 저장되고 전투 중 해당 효과를 실제로 억제한다.

### M7 — 모바일 실기기·배포 `P0 출시 게이트 / 보류`

재개 조건: 사용자가 모바일 검증 중단을 해제했을 때만 착수한다.

작업:

- Android export preset, 패키지 ID, 버전, 아이콘, 서명·배포 채널 정책을 확정한다.

- 10분 연속 실행의 FPS, 프레임 타임, 메모리, 발열, 배터리, 스피커 음량을 기록한다.

완료 조건:

- `export_presets.cfg`가 존재하고 승인 기기에서 설치·부팅·10분 완주가 가능하다.
- 크래시·입력 불능·안전 영역 침범이 0건이다.
- 데스크톱 헤드리스 성능 결과를 실기기 승인으로 대체하지 않는다.

## 7. v0.14 비모바일 완료 정의

다음이 모두 만족될 때 v0.14 비모바일 개선을 완료로 판정한다.

- M0의 실행 분포가 코드·문서·테스트에서 한 값으로 일치

- 1×/3× 표현과 음성 범위가 명시적으로 승인

모바일·배포 완료는 M7 재개 후 별도로 판정한다.
