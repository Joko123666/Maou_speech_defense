# 공식 난입 보스 아트 생성계획 재수립 — 2026-09-03

## 결론

공식 난입의 주 시각 자산은 `boss_5`·`boss_10`·`boss_15`·`final_boss`·`judgment_bell`의 기계/괴물 원본이 아니라 **미선택 후보와 그 진영 심복의 전용 난입 SD**여야 한다.

- 플레이어가 고른 후보는 라이벌 목록에서 제외한다.
- 남은 네 후보 진영이 한 번씩 공식 난입한다.
- 2:30·5:00·7:30은 각 경쟁 진영의 심복/간부가 등장한다.
- 10:00은 주요 경쟁 후보 본인이 등장한다.
- 기본 보스 5 ID는 체력·피해·행동·티어를 제공하는 전투 수치 껍데기이자 비선거 프로필/도감/치환 실패 폴백이다.

따라서 기본 보스 원본 5종의 스타일 정리는 폴백 품질 개선으로는 유효하지만, 공식 난입 보스 아트 생성의 중심으로 취급해서는 안 된다.

## 계획서 근거

`godot_formation_defense_gdd_v0_19.md`의 권위 계약은 다음과 같다.

- 7장: 한 후보를 선택하면 나머지 네 후보 진영이 네 번의 공식 난입권을 행사한다.
- 16장: 2:30은 경쟁 후보 A의 선봉/심복, 5:00은 경쟁 후보 B의 수석 심복·방해 책임자, 7:30은 경쟁 후보 C의 근위대장/강력 간부, 10:00은 주요 경쟁 후보 본인이다.
- 심복 중복 방지: 선택한 아군 심복이 경쟁 진영의 대표 심복과 같으면 적 슬롯을 `replacement_boss_id`로 교체한다.
- 데이터 목표: 후보의 `candidate_boss_id`와 심복의 `replacement_boss_id`를 안정 데이터로 관리한다. 현재 구현에서는 호환을 위해 심복 필드명이 `retainer_boss_id`다.

## 현재 구현 판정

### 정상 구현된 부분

- `CampaignStageResolver`가 선택 후보를 제외한 네 라이벌을 결정적으로 섞고 마지막 라이벌의 `candidate_boss_id`를 최종 슬롯에 예약한다.
- 앞 세 슬롯은 해당 라이벌의 기본 심복이 아군으로 선택되지 않았을 때 `retainer_boss_id`를 사용한다.
- `CampaignStageResolver`가 각 슬롯에 전투 수치 `boss_id`와 별도로 후보·심복·대체 수비병 표시 정체성을 기록하고, `GameController._apply_campaign_boss_character_art()`가 이를 직접 적용한다.
- 후보 5종과 심복 5종의 전용 좌향 난입 SD는 이미 활성 경로에 존재하며 512px 임포트·투명 배경을 사용한다.
- 캠페인이 없는 프로필이나 인물 치환을 적용할 수 없는 경우에만 `EnemyData.texture`의 기본 보스 원본이 표시된다.

### M0에서 바로잡은 부분

기존 보스 슬롯은 `boss_id`와 `faction_id`만 저장하고 표시 인물은 나중에 `boss_id`로 역추론했다. 선택 심복 중복을 피할 때 `faction.replacement_boss_ids`가 다른 기계 보스 ID를 빌려오므로 다음 오표시가 가능했다.

```text
예: 칸다를 아군으로 선택
→ 파르태손 진영이 중간 난입 슬롯에 배정
→ 칸다 대신 boss_10 수치 ID를 선택할 수 있음
→ retainer_for_boss(boss_10)으로 기븐을 역추론
→ 파르태손 색을 입힌 기븐이 대체 간부처럼 표시될 수 있음
```

이는 수치용 보스 ID와 화면 인물 ID가 결합된 문제였다. M0에서 슬롯에 `presentation_kind/presentation_id`와 snapshot revision 1을 추가해 해결했으며, 구형 revision 0 체크포인트는 기존 필드로 계속 읽는다.

## 공통 생성 사양

- 내장 ImageGen의 `identity-preserve` 또는 `style-transfer`를 사용하고, 수정은 `precise-object-edit`로 제한한다.
- 1254×1254 RGBA 투명 마스터, 네 변 최소 7% 안전 여백
- 적측 좌향, 중간 딥 네이비 외곽선
- 3~5개 넓은 색면, 최대 2단 셀 셰이딩, 제한된 하이라이트
- 보스 장식 예산 1.65는 허용하되 금속 재질 묘사·미세 패널선·입자 폭발로 실루엣을 덮지 않는다.
- 48px 아이콘 판독과 실제 158~224px 보스 판독을 모두 통과한다.
- 팩션 문양은 UI/전장 오버레이가 담당하므로 몸체에 큰 문양을 반복해서 그리지 않는다.
- 이미지 안에 문자, 숫자, 카드 프레임, 체력바, 바닥 전체 광원은 넣지 않는다.

## 구현 선행 계획

### M0 — 수치 ID와 표시 인물 ID 분리 `P0` · 완료

`StageRuntimeBossPlan.slots`를 다음 의미 구조로 확장한다.

```text
boss_id              = 체력·피해·행동 메커니즘
faction_id           = 색·문양·Prelude
presentation_kind    = candidate / retainer / guard
presentation_id      = 실제 표시할 후보·심복·대체 간부 ID
time                 = 등장 시각
```

- 최종 슬롯은 `candidate + rival_candidate.id`
- 일반 슬롯은 `retainer + rival.default_retainer_id`
- 선택 심복과 충돌하는 슬롯은 `guard + faction.id`
- `GameController`는 `boss_id` 역추론 대신 슬롯의 표시 정보를 그대로 전달
- 보스 경고, 체력 프레임, 결과 타임라인과 체크포인트도 같은 표시 ID 사용
- 이전 체크포인트에는 기존 `boss_id/faction_id`로 보수적 추론하는 이관 경로 제공
- 외부 팩에 `guard_intrusion_sd`가 없으면 해당 진영 친위대 전신을 좌우반전하고 문양을 붙이는 호환 폴백 사용

완료 기준은 선택 후보 5종×선택 심복 5종의 모든 조합에서 아군 후보/심복과 같은 인물이 적 보스로 동시에 표시되지 않고, 다른 진영 인물이 대체 간부로 잘못 추론되지 않는 것이다.

구현 결과:

- `StageRuntimeBossPlan` snapshot revision 1이 표시 종류와 안정 ID를 저장하며 revision 0을 호환 판독한다.
- 보스 본체·경고/체력 표시·결과 타임라인이 동일 슬롯 표시 정체성을 사용한다.
- M2 전에는 `guard_intrusion_sd/{faction_id}` 부재 시 해당 후보 Core의 `unique_tower_id` 수비병 전신을 좌우반전해 임시 표시했다. M2 이후 내장 카탈로그는 전용 5종을 사용하고 이 경로는 외부 팩 호환 폴백으로만 남는다.
- 5후보×5심복×3시드와 칸다/파르태손 충돌 회귀를 계약으로 고정했고 Godot 4.7 전체 품질 게이트 7/7을 통과했다.

### M1 — 실제 보스 표시 검수판 `P0` · 완료

- 기존 96/64/48px M4 검수판의 “staging-only” 표기를 현재 활성 상태로 교정
- 후보 5종을 최종 보스 224px, 심복 5종을 158/190/210px로 비교
- 진영색이 없는 실루엣만으로 후보·심복 10종을 구분하는 무채색 판독 행 추가
- 4개 슬롯을 함께 놓은 전장 밀도와 보스 경고/체력 프레임 결합 캡처 추가
- 여기서 실패한 기존 자산만 재생성 목록에 올림

구현 결과:

- 기존 M4 검수판을 스테이징 경로가 아닌 활성 `combat_sd`, `candidate_intrusion_sd`, `retainer_intrusion_sd` 경로로 교정하고 상태를 `approved_intrusion_set_active`로 갱신했다.
- `official_intrusion_boss_m1_candidates.png`에서 후보 5종 모두 224px 얼굴·대표 무기/효과·좌향 적대 포즈를 유지했다.
- `official_intrusion_boss_m1_retainers.png`에서 심복 5종 모두 158/190/210px 세 표시 단계의 역할 단서를 유지했다.
- `official_intrusion_boss_m1_monochrome.png`에서 10종 모두 128px 무채색 실루엣만으로 구분됐고, `official_intrusion_boss_m1_density.png`에서 4슬롯 전장·보스 경고/체력 프레임과 결합해도 겹침이나 과밀이 없었다.
- 검수한 기존 10종의 실패 ID와 선택 재생성 ID는 모두 0건이다. 따라서 M3 후보 보정은 필요하지 않으며 후속 M2에서 대체 간부 5종을 제작·활성화했다.

### M2 — 대체 간부 5종 제작 `P1` · 완료

1. 기존 친위대 대기/공격 전신을 정체성 참조로 사용
2. 좌향 적대 포즈와 후보 진영별 제한된 효과를 적용
3. 크로마/체커 배경이 생기면 연결 성분 기반 알파 정리
4. 84% 안전 영역으로 균일 정규화
5. 220/96/64/48px 검수판 승인 뒤 `guard_intrusion_sd`에 활성화

구현 결과:

- 내장 ImageGen으로 각 진영 친위대의 대기/공격 전신을 함께 참조해 파르태손 방패 돌진, 지아느 하트 글레이브 찌르기, 카스하 3안·무동공 나선 주문, 이레라이 뼈 미늘창·청록 불꽃, 주다긴다 대형 낫 횡베기의 좌향 적대 포즈 5종을 제작했다.
- `tools/prepare_guard_intrusion_art.ps1`로 생성 이미지의 체커/밝은 중립 배경을 연결 성분 기준으로 제거하고, 작은 하이라이트는 보존하면서 1254×1254 RGBA·84% 안전 영역·최소 100px 여백으로 정규화했다.
- 스테이징 `assets/graphics/style_refresh_v019/guard_intrusion_sd/`과 활성 `assets/graphics/guard_intrusion_sd/`의 5종 SHA-256이 일치하며, 런타임 import는 모두 512px 상한이다.
- `official_intrusion_boss_m2_guard_pairs.png`에서 아군 친위대 116px와 적 대체 간부 210px의 정체성 계승·자세 분리를, `official_intrusion_boss_m2_guard_sizes.png`에서 220/96/64/48px 판독성과 투명 배경·비클리핑을 승인했다.
- 내장 선거 카탈로그는 전용 `guard_intrusion_sd`를 반전 없이 사용한다. 해당 카테고리가 없는 외부 콘텐츠 팩만 기존 친위대 반전 폴백을 유지한다.

### M3 — 후보 최종 보스 선택 보정 `P1` · 생략(보정 대상 0종)

- 기존 5종을 우선 유지
- 48px에서 얼굴·대표 무기·방향 중 둘 이상이 사라지는 경우에만 재생성
- 후보의 아군 SD와 얼굴·뿔·주색은 공유하되, 좌향·적대 표정·공격 포즈·보스급 효과 중 세 요소 이상을 다르게 유지
- 후보별 별도 기계 괴물이나 종 골렘으로 변환하지 않음

M1 실전 크기·무채색·밀도 검수에서 후보 5종 모두 기준을 통과했으므로 M3 선택 보정은 수행하지 않는다.

### M4 — 통합·회귀 계약 `P1` · 완료

- 5후보×5심복 조합과 복수 seed에서 네 라이벌 진영·네 고유 표시 인물·정확한 최종 후보를 검사
- 일반 슬롯 `retainer/guard`, 최종 슬롯 `candidate` 범주를 고정
- 아군과 적의 동일 `presentation_id` 동시 존재 0건
- 후보/심복/대체 간부 15종의 활성 경로·SHA-256·RGBA·7% 여백·512px 임포트 검사
- Forward Mobile 1280×720 전체 스냅샷과 1600×720·1920×1080 반응형 검사
- 전체 7단계 품질 게이트와 Android APK 내부 15종 import/CTEX 포함 검사

구현 결과:

- `StageRuntimeBossPlanContractTest`가 5후보×5심복×3 seed의 75플랜·300슬롯을 모두 순회해 네 라이벌 진영/표시 ID 고유성, 아군 후보·심복 중복 0건, 앞 세 슬롯 `retainer/guard`, 마지막 슬롯 `candidate`를 검사한다.
- 300슬롯 각각에서 전투 본체가 `candidate_intrusion_sd`·`retainer_intrusion_sd`·`guard_intrusion_sd`의 직접 좌향 이미지와 같은 표시 ID를 사용하고 좌우반전하지 않는지 확인한다. 결과 타임라인은 같은 표시 ID를 유지하되 후보·심복은 승인 초상, 대체 간부는 전용 SD를 사용한다.
- manifest가 공식 난입 15종의 활성 경로와 고유 SHA-256, 1254px RGBA·7% 여백·512px import를 일괄 고정한다.
- 실제 resolver로 다섯 진영 guard 충돌 사례를 구성한 Forward Mobile 검수판을 1280×720, 1600×720, 1920×1080으로 캡처했다. 1600×720은 `stretch/aspect=keep`의 좌우 레터박스를 포함하며 세 화면 모두 잘림·겹침 없이 같은 16:9 구도를 유지했다.
- `audit_official_intrusion_apk.ps1`이 새 arm64 디버그 APK의 15개 import와 15개 고유 CTEX, staging/tests/tools/reference/data-art 0건, 권한 0개, zipalign, v2/v3 서명을 재현 가능하게 검사한다.
- 전체 7단계 품질 게이트 7/7을 통과했다. Android 실기기는 연결된 승인 기기가 없어 설치·실행·발열 검증을 완료로 표시하지 않는다.

## 생성하지 않을 항목

- 보스 시간대마다 같은 후보/심복의 별도 PNG 3~4벌
- 기계형 `boss_5`~`judgment_bell`을 미선택 후보 본인처럼 다시 디자인한 변형
- 후보 초상 이미지를 단순 좌우반전한 최종 보스
- 화면을 가리는 전신 오라·대형 입자 배경·텍스트가 포함된 이미지
- 데이터에 표시 ID가 연결되기 전의 대체 간부 이미지

## 우선순위와 중단 기준

1. **M0 표시 정체성 분리**가 끝나기 전에는 신규 대체 간부 이미지를 활성화하지 않는다.
2. 기존 후보/심복 난입 10종은 폐기하지 않고 실제 보스 크기 검수 결과를 기준으로 선별 보정한다.
3. 신규 생성은 대체 간부 5종부터 시작한다.
4. 기본 보스 5종은 비선거/도감/폴백 자산으로 유지하며 공식 난입 아트 품질 판정에서 분리한다.
5. 시각 검수에서 후보 본인과 심복/대체 간부가 즉시 구분되지 않으면 해당 진영만 재작업하고 전체 묶음을 다시 만들지 않는다.

## 최종 완료 정의

- 어떤 후보를 골라도 남은 네 후보 진영이 정확히 한 번씩 등장한다.
- 앞 세 슬롯은 심복 또는 같은 진영의 대체 간부, 마지막 슬롯은 미선택 후보 본인으로 보인다.
- 아군으로 선택한 심복이 적 보스로 중복 등장하지 않는다.
- 다른 진영의 인물이 팔레트만 바뀐 채 대체 간부로 표시되지 않는다.
- 공식 난입 15종과 기본 폴백 보스 5종의 역할이 데이터·코드·검수 문서에서 명확히 분리된다.

M0 런타임·저장·결과 계약, M1 기존 10종 실전 검수, M2 대체 간부 5종 생성·활성화, M4 다중 조합·반응형·Android 패키지 회귀를 모두 적용했다. M3 후보 보정 대상은 0종이므로 본 계획의 자동·데스크톱·패키징 범위는 완료됐고, 남은 승인은 Android 실기기 설치·가독성·성능·발열 검사다.
